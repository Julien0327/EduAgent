## 0. 文档说明与变更控制

### 0.1 文档地位

本文档与《产品设计方案 v2.1》共同构成执行期唯一技术基准。任何会话开工前必读；偏离必须走变更记录（产品方案 §0/§10 的规则对本文档同样生效）。

### 0.2 真实性约定（继承 v1，全文档强制）

- **§1「现状基线」只写已核实的代码事实**（2026-11-08 逐文件审计；2026-11-10 git 三点同步后刷新；2026-11-10 终审补充核对 API 路由清单、Python 环境与依赖状态）；**§2 起的目标态一律标注【目标】**。
- 未实测的数字标 `【待补充证据】`，禁止编造；证据产生后回填并删除标记。**性能/质量指标区分三种状态：「目标阈值」（设计值）→「待实测」→「已验证」（注明日期与数值）——禁止把目标写成已达成。**
- 环境与依赖核实结论注明核实日期（如"MCP SDK：2026-11-10 核实未安装"）。
- 文档中不出现 API Key、私钥、密码、token；AIC 身份码一律使用合成示例（如 `1.2.156.3088.1.ABC.XYZ.12345.0000.ABCD`），真实值仅经环境变量注入。
- 不写真实学校名、教师姓名。

### 0.3 技术不变式（整个执行期有效，防"顺手引入"）

1. **零重型框架（生产路径）**：不引入 LangChain/CrewAI/Redis/消息队列/前端框架/微服务。**边界（2026-11-10 终定）**：LangGraph **不进入本项目**——不进生产路径、不列为开发任务与验收、不因它增加周期与服务器依赖；仅为核心阶段完成后的个人学习项（§14 决策⑧）。MCP 于 Phase 5 **正式引入**（官方 SDK），作为能力开放出口，不改变内部编排。
2. LLM 仅 DeepSeek（OpenAI 兼容 SDK）；embedding 本地 bge-small-zh-v1.5，**经 ONNX Runtime CPU 推理（自导出 + 量化，服务器不装 torch）**，不调外部 embedding API。
3. 存储仅 SQLite（WAL 模式）+ 文件系统；不上 PostgreSQL/MySQL；**不引入向量数据库**（该规模下用 numpy 内存内积，见 §4.3）。
4. 所有密钥与令牌（`DEEPSEEK_API_KEY`、`EDUMATE_API_TOKEN` 等）只经环境变量；`.env` 不入库；源码与日志中不出现任何 token 明文。
5. 手写引擎不动摇：Planner→Workflow→Executor 主干保留，新能力以"新模块 + 节点改造"接入，不重写编排层；**不同时维护两套编排引擎**。
6. **术语命名纪律**：文档与简历只使用能被追问三层的准确术语（如 RAG、Critique Agent、A2A、MCP），禁止流行词堆砌与花哨包装；不将未完成的实践写成简历成果。
7. **危险操作禁令**：任何会话不得执行 `git reset --hard`、`git clean -fd`、未经检查的批量 `rm`、未经确认的批量 `.bak` 删除、任何可能覆盖或丢失服务器数据的操作。清理与删除类工作一律走「检查 → 备份 → 审核 → 确认 → 清理 → 验证」六步流程（§11.1）。

### 2.3 存储设计【目标】（SQLite 全表 schema）

```sql
-- ===== 知识图谱 =====
CREATE TABLE knowledge_points (
  kp_id        TEXT PRIMARY KEY,      -- 如 kp_quad_02（前缀=学科缩写）
  name         TEXT NOT NULL,
  subject      TEXT NOT NULL DEFAULT 'math',   -- schema 通用【决策②】
  stage        TEXT NOT NULL,         -- primary / junior
  grade        INTEGER,
  chapter      TEXT,
  difficulty   INTEGER DEFAULT 2,     -- 1-5
  description  TEXT,
  source       TEXT,                  -- 'curriculum' / 'manual'
  embedding    BLOB                   -- bge-small-zh-v1.5, 512d float32 序列化
);
CREATE TABLE kp_edges (
  from_kp    TEXT NOT NULL,           -- 前置知识点
  to_kp      TEXT NOT NULL,           -- 后继（学 to 前需先会 from）
  relation   TEXT DEFAULT 'prerequisite',
  PRIMARY KEY (from_kp, to_kp)
);

-- ===== 题库 =====
CREATE TABLE questions (
  q_id       TEXT PRIMARY KEY,        -- 如 q_00317
  stage      TEXT NOT NULL,
  subject    TEXT NOT NULL DEFAULT 'math',
  type       TEXT NOT NULL,           -- choice/fill/short/proof/application
  stem       TEXT NOT NULL,
  options    TEXT,                    -- JSON 数组（选择题）
  answer     TEXT NOT NULL,
  analysis   TEXT,
  score      REAL NOT NULL,
  difficulty INTEGER NOT NULL,        -- 1-5
  source     TEXT NOT NULL,           -- ape210k / math23k / llm_gen / manual
  status     TEXT DEFAULT 'active',   -- active / retired（质检剔除）
  created_at TEXT
);
CREATE TABLE q_kp (                   -- 题-知识点多对多
  q_id   TEXT NOT NULL,
  kp_id  TEXT NOT NULL,
  PRIMARY KEY (q_id, kp_id)
);
CREATE VIRTUAL TABLE questions_fts USING fts5(
  q_id UNINDEXED, stem, answer, tokenize='unicode61'
);

-- ===== 班级 / 学生 / 考试 / 答题（F16 Excel 导入，Phase 1）=====
-- 外键策略：连接时 PRAGMA foreign_keys=ON；默认 RESTRICT（产品不提供物理删除
-- 入口，防误删级联）；确需清除数据走显式管理脚本（双重确认），不走通用删除 API。
CREATE TABLE classes (
  class_id   TEXT PRIMARY KEY,        -- cls_<hash8>（导入时生成）
  name       TEXT NOT NULL,           -- 如 "初一（1）班"
  grade      INTEGER NOT NULL CHECK(grade BETWEEN 1 AND 12),
  stage      TEXT NOT NULL,           -- primary / junior / senior
  school     TEXT,                    -- 可选；演示/开源数据禁用真实校名（§0.2）
  import_batch_id TEXT,               -- 来源批次（软追踪，不建 FK）
  created_at TEXT NOT NULL,
  UNIQUE(name, grade, stage)          -- 班级识别键：同名同年级同学段视为同一班
);
CREATE TABLE students (
  student_id TEXT PRIMARY KEY,        -- stu_<hash8>（系统内 ID，与来源学号分离）
  class_id   TEXT NOT NULL REFERENCES classes(class_id),
  student_no TEXT NOT NULL,           -- 学号（关联标识，班内唯一）
  name       TEXT NOT NULL,
  import_batch_id TEXT,
  created_at TEXT NOT NULL,
  UNIQUE(class_id, student_no)
);
CREATE TABLE exams (
  exam_id     TEXT PRIMARY KEY,       -- exam_<hash8>
  title       TEXT NOT NULL,
  class_id    TEXT REFERENCES classes(class_id),   -- 可空 = 多班联考
  exam_date   TEXT,                   -- ISO 日期
  subject     TEXT NOT NULL DEFAULT 'math',
  stage       TEXT,
  total_score REAL,
  import_batch_id TEXT,
  created_at  TEXT NOT NULL
);
CREATE TABLE exam_questions (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  exam_id   TEXT NOT NULL REFERENCES exams(exam_id),
  q_no      INTEGER NOT NULL CHECK(q_no > 0),      -- 卷面题号
  q_id      TEXT REFERENCES questions(q_id),       -- 可空 = 外部题（未挂题库）
  kp_ids    TEXT,                                   -- JSON 数组：导入时人工关联
  score     REAL NOT NULL CHECK(score > 0),        -- 卷面分值
  stem      TEXT,                                   -- q_id 为空时必填（校验器保证）
  answer    TEXT,
  UNIQUE(exam_id, q_no)
);
CREATE TABLE student_answers (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  exam_id    TEXT NOT NULL REFERENCES exams(exam_id),
  student_id TEXT NOT NULL REFERENCES students(student_id),
  exam_q_id  INTEGER NOT NULL REFERENCES exam_questions(id),
  score      REAL NOT NULL CHECK(score >= 0),      -- 0 ≤ 得分 ≤ 该题分值（应用层校验）
  is_correct INTEGER,                              -- 0/1，可空（主观题未判）
  UNIQUE(exam_id, student_id, exam_q_id)           -- 数据库级防重复累计
);
CREATE TABLE import_batches (
  batch_id     TEXT PRIMARY KEY,      -- imp_<hash8>
  kind         TEXT NOT NULL,         -- full / classes / students / exam / answers
  file_name    TEXT,
  file_sha256  TEXT NOT NULL,         -- 指纹：与 kind 联合判重
  status       TEXT NOT NULL DEFAULT 'pending',
               -- pending / validating / committed / partial / failed
  total_rows   INTEGER DEFAULT 0,
  ok_rows      INTEGER DEFAULT 0,
  failed_rows  INTEGER DEFAULT 0,
  error_report TEXT,                  -- JSON：[{sheet,row,field,level,code,message}]
  created_at   TEXT NOT NULL,
  committed_at TEXT
);

-- ===== 会话与消息（F1/F14）=====
CREATE TABLE sessions (
  session_id TEXT PRIMARY KEY,
  title      TEXT,
  created_at TEXT, updated_at TEXT
);
CREATE TABLE messages (
  msg_id     INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  role       TEXT NOT NULL,           -- user / assistant
  content    TEXT NOT NULL,
  task_id    TEXT,                    -- 关联产生的任务
  created_at TEXT
);

-- ===== 任务与 Trace（F10/F14，替换内存 TaskStore）=====
CREATE TABLE tasks (
  task_id    TEXT PRIMARY KEY,        -- uuid4 hex[:12]，沿用现格式
  session_id TEXT,
  prompt     TEXT NOT NULL,
  status     TEXT NOT NULL,           -- pending/running/done/failed
  workflow   TEXT,
  params     TEXT,                    -- JSON
  error      TEXT,
  created_at TEXT, started_at TEXT, ended_at TEXT
);
CREATE TABLE steps (
  task_id        TEXT NOT NULL,
  step_no        INTEGER NOT NULL,
  node           TEXT NOT NULL,       -- 节点名，与 SSE 事件一致
  status         TEXT NOT NULL,
  input_summary  TEXT,                -- 截断 500 字符
  output_summary TEXT,                -- 截断 500 字符
  tokens_in      INTEGER DEFAULT 0,
  tokens_out     INTEGER DEFAULT 0,
  cost           REAL DEFAULT 0,      -- 按 token 单价表核算
  latency_ms     INTEGER DEFAULT 0,
  error          TEXT,
  started_at     TEXT, ended_at TEXT,
  PRIMARY KEY (task_id, step_no)
);

-- ===== 评测（F12）=====
CREATE TABLE eval_cases (
  case_id TEXT PRIMARY KEY,
  prompt  TEXT NOT NULL,
  expect  TEXT NOT NULL,              -- JSON：{workflow, params, artifacts_min}
  tags    TEXT                        -- JSON 数组：core/boundary/retrieval...
);
CREATE TABLE eval_runs (
  run_id    TEXT PRIMARY KEY,
  case_id   TEXT NOT NULL,
  mode      TEXT NOT NULL,            -- fake / online
  passed    INTEGER NOT NULL,
  metrics   TEXT,                     -- JSON：该用例各指标结果
  detail    TEXT,
  created_at TEXT
);

-- ===== 关键索引 =====
CREATE INDEX idx_students_class   ON students(class_id);
CREATE INDEX idx_exams_class      ON exams(class_id);
CREATE INDEX idx_examq_exam       ON exam_questions(exam_id);
CREATE INDEX idx_answers_exam_stu ON student_answers(exam_id, student_id);
CREATE INDEX idx_answers_q        ON student_answers(exam_q_id);
CREATE INDEX idx_batches_status   ON import_batches(status);
CREATE INDEX idx_messages_session ON messages(session_id);
CREATE INDEX idx_tasks_session    ON tasks(session_id);
```

- **表间关系**：`classes 1:N students`；`classes 1:N exams`（可空）；`exams 1:N exam_questions`；`exam_questions N:1 questions`（可空，外部题不入题库）；`student_answers` 三向关联 `exams × students × exam_questions`（UNIQUE 三元组）；`exam_questions.kp_ids` / `q_kp` 提供题目-知识点挂接（导入人工关联与题库自动挂接并存，诊断时合并取用）。
- **完整性约束**：得分范围 0≤score≤该题分值由应用层在关联校验与事务写入时双重核对（SQLite CHECK 无法跨表）；`is_correct` 与得分>0 的一致性仅告警不强制（主观题部分得分合法）。
- **导入追踪**：各业务表携带 `import_batch_id` 软关联 `import_batches`（不建 FK，批次表是审计记录，删除批次不影响业务数据）；批次报告记录逐行写入结果。
- **迁移思路**：当前无业务库（TaskStore 内存态、种子走 JSON），Phase 1 首次建库即含全部表；`migrations.sql` 版本化（V1=全量 DDL，后续增量按序号追加）；服务器 `data/db/` 当前无旧库，如未来出现则按迁移序执行。**本轮不改任何数据库文件。**

引用的存储：引用清单随产物元数据存 JSON 文件（`data/outputs/{task_id}/citations.json`，schema 见 §4.4），不单独建表。

## 3. 数据工程方案【目标】（Phase 1）

### 3.1 知识点图谱

- **来源**：公开课程标准（义务教育数学课程标准）的内容域拆解；不爬内部教材。
- **规模目标**：初中全量 ≥300 个知识点，grade 7–9，含章节归属。
- **构建流程**：课标文本 → 按内容域拆条（脚本辅助 + 人工核对）→ 结构化入库 → 依赖边标注（先修关系，重点：数→式→方程→函数主线、几何推理链）→ 抽样复核 20%。
- **小学部分**：从 APE210K 自带知识点标签聚合出高频知识点（约 80–120 个），供小学题库挂接【决策①】。
- **验收**：图谱加载入 SQLite；每知识点有 ≥0 条前置边且全图连通性合理（主干链无孤岛）；loader 校验脚本对图谱做 fail-fast。

### 3.2 题库管线

| 来源 | 用途 | 规模 | 许可/合规 |
|---|---|---|---|
| APE210K（开源数据集） | 小学题库打底 | 引入 ≥2 万题 | 研究用途许可，注明出处【决策①】 |
| Math23K | 小学补充（含答案+表达式） | 视质量引入 | 同上 |
| LLM 生成（DeepSeek） | 初中题库（小学覆盖不到的学段做深） | 2–3 千题，全部过质检环（F4）与人工抽检 | 自产，人工审核 ≥10% |
| 人工精修 | 评测 golden 依据题、示例题 | ~50 题 | 自产 |

- **ETL**：下载 → 字段映射（题干/答案/类型/难度粗标）→ 清洗（去重、去残缺、LaTeX 规范化）→ 入 SQLite + FTS5 索引。
- **LLM 打标**：知识点挂接（从图谱候选中选）、难度 1–5 标定；few-shot + temperature≤0.2；**抽检 ≥10% 人工核对，合格率 ≥90% 方可批量采用**，不合格则修 prompt 重跑。
- **数据字典**：见 §2.3 schema；入库脚本幂等（可重跑不重复插入）。
- **验收**：题库 ≥2 万；随机抽 100 题人工检查字段完整率 ≥95%；打标抽检合格率 ≥90%。

### 3.3 数据质量守门

- 入库前校验器（复用 fail-fast 思想）：必填字段、题型枚举、难度范围、kp_id 必须存在于图谱。
- 质检剔除的题 `status='retired'` 保留可追溯（不物理删除）。

### 3.4 学生与答题数据导入管线【目标】（Phase 1·决策⑩）

数据来源 = **Excel 模板导入**（不做在线作答系统）。模板字段设计见产品方案 F16（五种工作表逐一列明）；本节定义管线与事务语义。

**七步流程**：

```
Excel 解析（openpyxl 只读流式，防大文件 OOM）
  → 字段映射（表头→schema 字段，别名归一）
  → 格式校验（必填/类型/枚举/范围；暂存内存 staging，不写业务表）
  → 关联校验（班级①→学生②→考试③→题目④ 标识链逐级定位）
  → 重复检测（批内重复行 + 库内 UNIQUE 预检 + 批次指纹判重）
  → 事务写入（单事务 BEGIN IMMEDIATE；应用层完整性兜底）
  → 批次状态更新 + 导入结果报告
```

**校验规则**：必填缺失/类型非法/枚举越界/范围越界（grade 1–12、score>0、0≤得分≤该题分值）/关联断裂（四级标识定位失败）/完整性（每考试 ≥1 题、total_score 与分值合计不一致→warning）/重复（批内与库内）。

**事务与异常**：

- 校验阶段不写业务表（staging 在内存，单批上限 `IMPORT_BATCH_MAX_ROWS=5000`）。
- 写入阶段单事务；**不可恢复错误**（解析失败、关联大面积断裂、约束冲突）→ 整批回滚，批次 `failed`，不留部分写入。
- **行级错误** → 合法行写入，批次 `partial`，报告明示 ok/failed 计数——**不得呈现为完整成功**。
- 状态机：`pending → validating → committed | partial | failed`；进程中断 → 未提交事务由 SQLite 自动回滚；服务启动时将滞留 `validating` 的批次清扫为 `failed`。
- **并发**：应用级互斥——存在 `validating` 状态批次时拒绝新导入（409）；导入接口限流 10/min（§10.5）。

**重复导入策略**：

- 批次指纹 = `kind + file_sha256`；命中已 `committed/partial` 批次 → **默认拒绝**并返回原批次报告。
- 答题记录支持**显式覆盖重导**（`force=true`：同一事务内先删该考试原 answers 再写入，前端二次确认）——唯一允许的覆盖通道。
- 数据库层 `UNIQUE(exam_id, student_id, exam_q_id)` 兜底，**杜绝答题记录重复累计**。

**验收**：合法导入/含错文件→报告准确定位 sheet+行+字段/重复导入拒绝/覆盖重导/中断回滚后无部分写入，五类用例单测全过；错误报告定位精度 100%。

## 4. 检索方案【目标】（Phase 2）

### 4.1 受限域 NL 问数（题库问数，非开放域 NL2SQL）

- **路线**：不生成自由 SQL。任务参数 → **SQL 模板 + 参数化绑定**（本节是 §4.2 阶段 2 结构化过滤的实现细则）：

| NL 意图 | 参数 | SQL 子句（模板） |
|---|---|---|
| 指定章节/知识点 | chapter / kp_ids | `JOIN q_kp ON kp_id IN (?,?,...)` |
| 难度 | difficulty | `WHERE difficulty = ?` 或 `BETWEEN ? AND ?` |
| 题型 | question_types | `WHERE type IN (?,?,...)` |
| 题量 | count | `ORDER BY ... LIMIT ?` |
| 总分约束 | total_score | 不进 SQL——由组卷配平器处理（候选集选出后按题型分值贪心配平） |

- **安全**：全部参数化查询（占位符），禁止字符串拼接 SQL；参数白名单校验。
- **验收**：§9 各参数字段在组卷结果上的一致率 ≥95%；注入用例（golden set boundary 组）全部被拦截。

### 4.2 三阶段检索架构【目标】（知识点召回与题目检索分离）

**原则：知识点召回和题目候选检索是两个不同阶段；不同检索对象（知识点文本 vs 题目文本）的分数不可直接混合相加。**

**阶段 1 知识点召回**（对象=知识点）

1. 查询解析：planner 已抽取的结构化条件 + 口语查询上下文改写（模板拼接，如"二次函数图像"→拼接学段上下文）。
2. 双路召回：FTS5 关键词（知识点 name/description）+ 向量（知识点描述，§4.3）。
3. 融合：两路分数**各自归一化**（FTS5 bm25 rank 归一化、内积相似度 min-max）后加权 `score = α·kw_norm + (1-α)·vec_norm`，`α=0.4` 起步（`RETRIEVAL_ALPHA`），评测期只允许整档调整（0.3/0.4/0.5）并记录效果差 → 去重 → 规则重排（章节/学段匹配加分）→ 输出相关知识点集合 top-k（默认 k=10）。

**阶段 2 题目候选扩展**（对象=题目，结构化为主）

1. 以阶段 1 知识点集合经 `q_kp` 关联 JOIN 扩展题目候选。
2. 结构化过滤：学段/学科/年级/难度/题型/分值/状态（active）——全部参数化 SQL（§4.1）。
3. 必要时题目自身 FTS5（`questions_fts`）补充候选（按题面关键词找题）；补充候选同样须落回知识点关联校验。

**阶段 3 题目重排**（对象=题目，独立评分）

- 评分特征（**各自归一化后加权，不与阶段 1 知识点分数直接相加**）：
  - 知识点匹配度：候选题关联 kp 与阶段 1 集合的重合度（全中 > 部分中）；
  - 结构化贴合度：难度偏移惩罚、题型权重、分值可用性（组卷配平视角）；
  - 题面相关性：FTS5 rank 归一化（仅在有题面检索意图时计入）。
- 权重起步值与整档调整纪律同 α；**不引入交叉编码器**（2C2G 算力不允许，如实向面试官说明取舍）。

### 4.3 向量检索（ONNX）【决策⑤⑥⑦ 定案 2026-11-10】

- **模型与运行时**：`bge-small-zh-v1.5`，**经 ONNX Runtime CPU 推理**——开发机用 transformers+torch 导出并 int8 动态量化一次（`scripts/export_bge_onnx.py`）；**服务器只装 onnxruntime（~60MB）+ tokenizer，不装 torch**。
- **嵌入对象决策（关键，面试考点）**：**只嵌知识点描述，不嵌题目**。理由：① 题目由结构化条件（知识点/难度/题型）精确过滤即可，向量语义检索题干会引入噪声；② 知识点描述短文本、语义密度高，向量收益最大；③ 索引与内存开销小一个数量级。若未来出现"按题意找相似题"需求，再评估题目向量（记录为变更，不预先实现）。
- **索引（不引入向量库）**：**纯 numpy 内存内积**——千级知识点 × 512d float32 ≈ 6MB，服务启动时从 `knowledge_points.embedding` BLOB 载入为矩阵，查询时内积取 top-k。千级规模引入 sqlite-vec/FAISS 属过度设计（此取舍可作面试素材）；若未来题目向量使规模上万，再评估向量库（走变更记录）。

## 5. 学情根因归因【目标】（Phase 3）

### 5.1 掌握度模型与数据边界

- 知识点掌握度 = 该知识点关联题目的正确率加权均值（近期权重 > 远期，权重比 2:1）；样本 <3 题标记 `insufficient`。
- **数据来源（决策⑩联动）**：掌握度只从 `student_answers`（§2.3，Excel 导入）经 `exam_questions → q_kp`（或 `exam_questions.kp_ids` 导入人工关联）聚合。**F7 正式诊断输入只认导入的真实数据**：demo 种子数据仅限开发/评测环境（`DATA_ENV=dev` 标识）；演示/生产环境下无导入数据时，诊断接口拒绝输出正式结论并提示"请先导入班级数据"，**不以模拟数据或模型推测冒充学情结论**。
- 薄弱点阈值：mastery < 0.6（沿用现有口径，保持一致性）。

### 5.2 归因算法（规则出骨架，LLM 只做叙述）

1. 取薄弱点集合 B（按 mastery 升序）。
2. 对每个 b∈B：沿 `kp_edges` 反向回溯前置链，检查各前置知识点的掌握度。
3. 归因规则：前置链上 mastery < 0.7 的最深节点记为根因候选；若前置全部良好，则 b 本身为根因。
4. 归因链输出：`{根因: kp_x, 路径: [kp_x → ... → b], 证据: [(q_id, 对/错)...], 置信: high/mid/low}`——**确定性规则，可单测**。
5. LLM 叙述化：把归因链转成教师可读的一段话 + 建议措辞；LLM 不参与归因判断本身（保证可解释、可复现）。
6. 输出必须标注数据范围（涉及的考试数/题目数/学生数），供使用者判断结论强度。

### 5.3 推荐练习

按根因知识点从题库检索（§4.2 阶段 2/3），每根因推荐 3–5 题，难度贴近学生水平（薄弱 → 降 1 档起步）。

### 5.4 验收

构建 10 例 ground truth 案例（预置答题数据中人为构造特定薄弱模式，仅用于评测）归因一致率 ≥80%；每个归因链在报告与前端均可展开证据；**数据不足（<3 题/无导入数据）时明确返回 insufficient 与原因，不输出推测性结论**；另以导入的真实班级数据（≥1 班 ≥1 考试）跑通端到端归因。

## 6. Trace 与可观测【目标】（Phase 3）

### 6.1 采集机制

- **包装器统一采集**：Workflow 执行器在每节点前后调用 `tracing.collector`，写 `steps` 表；节点代码无需感知（除 A2A 节点补充 metadata）。
- 采集失败只告警不阻断任务（try/except 隔离）。
- SSE step 事件扩展字段：`tokens_in/tokens_out/cost/latency_ms`（前端时间线直接可用）。

### 6.2 成本核算

- token 单价配置化（`config.py`：`PRICE_PER_1K_IN` / `PRICE_PER_1K_OUT`，默认按 DeepSeek 公开牌价，标注"按当时牌价估算"）。
- 步骤成本 = tokens×单价；任务成本 = Σ步骤；日汇总由 SQL 聚合。**Σ(steps.cost) = tasks 级成本必须可复算（单测断言）**。

### 6.3 与 AMP 日志的关系（面试考点，写清防混淆）

AMP（interop 层）是**协议层审计日志**（面向国标平台的调用留痕）；`steps` 表是**业务层 Trace**（面向开发者/教师的执行回放与成本观测）。两者独立，互不替代。

### 6.4 验收

Trace 覆盖三条工作流 100% 步骤；任一历史任务重启后可回放；成本面板数字与 SQL 聚合一致。

## 7. 多轮会话与持久化【目标】（Phase 2）

### 7.1 会话机制

- `POST /api/chat` 增加 `session_id`（缺省新建会话）；planner 每轮注入最近 N=6 轮消息 + 会话内已完成任务的摘要（任务名+参数，不贴全文）。
- 追问策略（F1）：planner 输出增加 `need_clarification` 通道，信息不足时生成至多 2 轮追问，超限降级默认值执行并在结果注明。

### 7.2 上下文管理

- 消息超长：每轮截断至 2000 字符入上下文（原文全量落库）。
- 会话与消息、任务三方以 `session_id`/`task_id` 关联，前端会话切换时回放消息与任务卡。

### 7.3 任务持久化

- TaskStore 接口不变（`create/get/update`），实现从内存 dict 换为 SQLite（进程内缓存读、写穿透）；**接口不变意味着工作流层零改动**。
- 并发：SQLite WAL + 单写连接队列；产物文件路径继续由 file_store 管理（文件系统不动）。

### 7.4 验收

重启恢复测试（杀进程→重启→任务/会话/Trace 可查）；并发 10 任务提交无错乱（WAL 下写不冲突）。

## 8. 质检环与 MCP 能力开放【目标】（Phase 5·决策③）

### 8.1 质检 critique 环设计

- **独立质检 agent**：`critique/checker.py`，输入=生成题+图谱上下文，输出=结构化质检结论（correct/difficulty/duplicate 三维 + 总裁定）。
- 三维校验：
  - 正确性：答案自洽校验（数值题代回验证、选择题答案在选项内、应用题单位/量纲合理性规则）+ LLM 复核一题一验；
  - 难度复核：与标注难度档位的偏离判定（规则：题干长度/步骤数代理指标 + LLM 五档复判，不一致以规则优先）；
  - 查重：与题库现有题做 FTS5 关键词 + 编辑距离相似度，阈值告警。
- **回流**：不合格 → 携带质检原因重生成，至多 2 轮；仍不合格 → 剔除（`status='retired'`）并在任务结果中报告缺口。

### 8.2 质检指标

- 拦截率 = 判不合格题数 / 送检题数；回流收敛 = 平均通过轮次；两项进评测报告页。
- 质检 agent 不可用 → 跳过并 warning，不阻塞主流程（降级一致于现有三级降级思想）。

### 8.3 MCP 能力开放【决策③⑫·正式范围】

**定位**：把系统已有能力以 MCP（Model Context Protocol）标准开放给外部 AI 客户端/智能体——与 AIP 国标互补（AIP 面向梧桐平台生态，MCP 面向通用 MCP 生态），两条出口互不影响。

**SDK 与版本核实**：

- 官方 `mcp` Python SDK——**2026-11-10 核实：当前环境未安装，requirements.txt 无此依赖**，标注为**计划新增依赖**；Phase 5 安装时锁定确切版本写入 requirements.txt。
- 安装后先以最小连通性脚本验证再编码：服务端创建方式（FastMCP 实例化）、工具注册方式（装饰器/类型注解生成参数 Schema）、stdio 启动方式、Streamable HTTP 挂载方式，**全部以安装版本的官方文档为准，不凭印象写 API，不拼接不同版本示例**。

**传输方式【决策⑫】**：

| 传输 | 场景 | 安全要求 |
|---|---|---|
| **stdio** | 本地：受信本地宿主进程（Inspector、桌面 AI 助手） | 不监听网络端口、不默认暴露公网服务；工具调用仍走服务层校验 |
| **Streamable HTTP** | 远程：网络访问 | **必须** Access Token 认证（§10.5）+ 请求限流 + 敏感工具授权；挂载于 FastAPI |

- 远程传输采用 **Streamable HTTP**（MCP 规范 2025-03-26 版起取代旧式 HTTP+SSE 传输）；新项目不使用旧式 SSE 作为远程传输。

**三个工具定义**（全部复用业务服务层，**不在 MCP 层重新实现检索/题库/诊断逻辑**；handler 只做参数适配）：

| 工具 | 输入参数 | 输出结构 | 错误处理 | 业务服务 | 权限边界 |
|---|---|---|---|---|---|
| `search_knowledge_points` | `query: str`*；`stage?: str`（枚举）；`top_k?: int`（1–20，默认 5） | `{points: [{kp_id, name, stage, grade, chapter, score}], citations: [kp_id]}` | query 空 → 参数错误；无结果 → 空列表 + message | retrieval（§4.2 阶段 1） | 只读；不含学生数据；两种传输均可用 |
| `query_question_bank` | `kp_ids?: [str]`；`chapter?: str`；`difficulty?: int`（1–5）；`q_type?: str`（枚举）；`count?: int`（1–50，默认 5） | `{total, truncated, questions: [{q_id, stem, type, difficulty, score}]}` | count 超上限截断并标 `truncated`；候选不足如实返回缺口 | 题库问数（§4.1 + §4.2 阶段 2/3） | 只读；不含学生数据 |
| `diagnose_learning_gaps` | `exam_id?: str`；`class_name?: str`；`student_no?: str`（三选一组合定位） | `{scope: {exams, students, answers}, gaps: [{root_kp, path, confidence}], insufficient?: reason}` | 定位失败 → NOT_FOUND；数据不足 → `insufficient`（不推测） | diagnosis（§5） | **敏感工具**：访问学生答题数据；远程传输必须持授权 token（作用域配置）；输出默认只含归因结论与题号级证据，学生姓名按配置脱敏 |

- **服务层复用与安全一致性**：参数白名单、SQL 参数化、数据边界校验在服务层统一生效，MCP 与 REST 两条入口调用同一服务函数；单测同时覆盖两条入口。
- **验收**（与安装 SDK 版本兼容的 MCP Inspector 或等效客户端）：服务启动（stdio + Streamable HTTP）；工具发现；3 工具参数 Schema 展示；3 工具实际调用；正常与异常响应（非法参数/无结果/数据不足）；**远程认证失败返回 401、未授权调用敏感工具被拒绝**；含离线单测（FakeLLM）。

## 9. 评测体系【目标】（Phase 4）

> 评测先行纪律：Phase 2 起任何检索/归因改动，先跑评测记录 baseline，改动后对比。指标口径如下，**判定脚本与口径一一对应，禁止口头上"我觉得变好了"**。

### 9.1 指标定义（精确口径）

| 指标 | 精确定义 | 判定方式 |
|---|---|---|
| 任务成功率 | 评测集上 `status=done` 且产物清单 ⊇ `artifacts_min` 的比例 | 自动 |
| 参数字段准确率 | planner `params` 与 golden `expect.params` 在字段集（workflow/subject/chapter/count/difficulty/question_types/total_score）上的字段级一致率；chapter 允许同义白名单匹配 | 自动 |
| recall@k / MRR | §4.5 口径（知识点阶段 50 条标注查询） | 自动 |
| judge 五维 | LLM-as-judge 对产物按 5 维（内容正确性/难度适切/覆盖完整/表述规范/引用规范）1–5 分 | 自动 + 校准 |
| judge 校准一致率 | judge 与人工在同 50 题上的分档（四舍五入）一致比例；**≥80% 采信 judge 全量打分，否则回退规则评分并记录** | 半自动 |
| p95 延迟 | 任务 submitted→ended 的分布 p95，分工作流统计 | 自动（steps/tasks 时间戳） |
| 单任务成本 | Σ steps.cost（¥） | 自动 |
| 质检拦截率 / 回流收敛轮次 | §8.2 口径 | 自动 |
| 归因一致率 | §5.4 的 10 例 ground truth 一致率 | 自动（预置答案） |

### 9.2 golden set

- 规模 ≥100 条，其中边界用例 ≥20%（模糊表述、参数冲突、注入尝试、超范围请求、题量缺口）。
- 单条格式：

```json
{"case_id": "gc_001",
 "prompt": "请对《一元二次方程》做章节小测并生成学情报告",
 "expect": {"workflow": "exam_loop",
            "params": {"chapter": "一元二次方程", "count": 10, "total_score": 100},
            "artifacts_min": ["试卷.docx", "答题卡.xlsx", "学情报告.pdf"]},
 "tags": ["core", "chapter"]}
```

- 维护规则：评测失败的修复不得通过改 golden 硬凑——改 golden 必须走变更记录并给理由。

### 9.3 执行方式

- 两档：`fake`（FakeLLM，CI 每次 push 跑 20 条 smoke，<2 分钟）/ `online`（真实 DeepSeek，全量 100+ 条，本地跑，结果落 `eval_runs`）。
- runner 幂等：同一 case 重复执行覆盖同 run_id 结果集。

### 9.4 报告与 CI

- `GET /api/eval/report`：各指标 baseline→current、近 5 次 run 对比。
- GitHub Actions：push 触发 pytest 全量 + smoke eval 20 条；失败即红。

### 10.5 API 安全（认证与限流）【目标·决策⑪】

**认证**：

- `EDUMATE_API_TOKEN` 环境变量注入（§0.3-4），不硬编码、不入库、不进日志。
- FastAPI dependency 校验 `Authorization: Bearer <token>`（兼容 `X-API-Token` 头）；常量时间比较（`secrets.compare_digest`）。
- 未配置 token → 启动告警且敏感请求 fail-closed（仅 `/api/health` 可用）。

**保护范围（2026-11-10 核实的现有 7 端点逐项 + 新增端点）**：

| 端点 | 认证 | 限流（默认，配置化） | 说明 |
|---|---|---|---|
| `GET /api/health` | 免 | 免 | 存活探针，不返回敏感信息 |
| `POST /api/chat` | ✅ | 30/min/IP | 触发 LLM 调用（有成本） |
| `POST /api/tasks` | ✅ | 30/min/IP | 触发工作流执行（有成本） |
| `GET /api/tasks/{id}` | ✅ | 120/min/IP | 任务回查（含产物元数据） |
| `GET /api/tasks/{id}/events`（SSE） | ✅ | 30/min/IP | 实时进度流 |
| `GET /api/tasks/{id}/files/{name}` | ✅ | 60/min/IP | 产物文件下载 |
| `GET /api/tasks/{id}/preview/{kind}` | ✅ | 60/min/IP | HTML 预览 |
| 新增 sessions / trace / citations | ✅ | 120/min/IP | 业务数据查询 |
| 新增 stats / eval | ✅ | 60/min/IP | 内部接口（限内网/管理员 token 作用域） |
| 新增 `/api/import` 三端点 | ✅ | 10/min/IP | 学生数据导入（敏感） |
| AIP `/rpc` 与 ADP 发现 | mTLS（既有） | — | interop 通道不变 |

**限流实现**：进程内滑动窗口中间件（自写 ~50 行，单实例部署前提下够用；分布式限流随多实例需求走变更记录）。超限响应 `429 + Retry-After`；连续超限记 warning（不含 token）。

**异常处理**：`401`（缺/错 token，不区分二者以防探测）、`403`（token 无该接口/工具权限）、`429`（限流）；统一异常处理器，响应体不含内部细节。

**日志脱敏**：token 与 Authorization 头绝不入日志；学生姓名/学号在应用日志中脱敏（如`张*`/学号后 4 位）；导入错误报告含行级数据，仅在接口响应返回，服务端日志只记批次号与计数。
