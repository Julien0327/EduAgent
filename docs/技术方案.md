## 1. 作品概述

### 1.1 一句话定位

**一个"懂教学、会做文件、能互联"的教学任务自动化智能体：教师用自然语言下达教学任务，Agent 自动编排文档处理工具，产出可直接使用的教学文档（试卷 / 答题卡 / 学情报告 / 教案），并作为 AIP Partner 通过标准协议对外提供教学能力。**

### 1.2 产品名称

- 中文名：**智教助手**
- 英文名：**EduMate**（Education + Mate / Automate）
- 智能体身份名（AIP 能力名）：**EduMate-AIP**

### 1.3 核心能力

| 能力 | 说明 | 对应工作流 |
|---|---|---|
| 章节小测一条龙 | 检索知识点 → 出卷 → 试卷(docx) → 答题卡(xlsx) → 加载预置答题 → 成绩统计 → 学情报告(pdf) | `exam_loop` |
| 智能组卷 | LLM 实时命制题目，产出试卷(docx)与答题卡(xlsx) | `question_gen` |
| AI 教案生成 | LLM 生成结构化教案（目标/重难点/过程/作业），产出 docx | `lesson_plan` |
| 智能体互联 | 作为 AIP Partner 暴露 `/rpc` + `/health`，学情诊断节点可经 Discovery→RPC 调用外部 Agent，失败自动回退本地 | `interop/` 适配层 |

### 1.4 技术选型总览

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.11+ | 文档处理生态最强 |
| 后端 | FastAPI | 异步/同步皆可，自动 OpenAPI |
| 前端 | 原生 HTML + CSS + JavaScript（无构建、无框架） | FastAPI 静态托管，轻量 |
| 文档 | python-docx / openpyxl / pandas / reportlab | Word / Excel / 数据分析 / PDF |
| 模板 | Jinja2 | Word/Excel 内容 → HTML 预览页 |
| LLM | DeepSeek（`deepseek-v4-flash`，OpenAI 兼容） | 文本任务 |
| 智能体互联 | 官方 `acps-sdk==2.2.0` + 自研 `interop/` 适配层 | AIC/ACS/ADP/AIP/AMP 五件套 |
| 存储 | 本地文件系统 + JSON 种子数据 | 无数据库 |
| 日志 | 标准库 `logging` | 控制台 + 文件，含 task_id 绑定 |

**明确不引入**：MySQL/Redis、Docker、微服务、用户登录、LangChain/LangGraph 等重型框架。

## 2. 需求分析

### 2.1 目标用户

| 用户 | 优先级 | 说明 |
|---|---|---|
| 一线中小学教师（主科：数/语/英） | ★★★ 核心 | 文档工作最重，出题/批改/统计/报告耗时高 |
| 教研组 / 年级组 | ★★ | 统一命题、组卷、考后统一分析 |
| 教培机构教师 | ★★ | 出题 + 个性化反馈报告 |

### 2.2 用户痛点

1. **出题耗时**：手动组卷 30–60 分钟/套，还要排版、配评分标准、做答题卡。
2. **成绩统计繁琐**：Excel 里写公式算平均分/及格率/优秀率/排名，易出错、重复劳动。
3. **学情分析难**：只知道分数，不知道"哪个知识点没掌握、该补什么、怎么分层"。
4. **文档格式劳动**：把分析结果做成 Word/PDF 报告要大量排版时间。
5. **通用 AI 帮不上忙**：聊天工具只能"说"答案，不能直接产出带格式的试卷与报告文件。

### 2.3 核心场景

- 单元/课堂小测组卷（知识点 → 题型 → Word 试卷 + Excel 答题卡）
- 成绩录入分析（读成绩表 → 自动统计）
- 学情分析报告生成（成绩 + 错题 → 知识点掌握度 → PDF 报告）
- 教案 / 讲义生成（主题 → Word 文档）

### 2.4 标志性 Demo 场景（章节小测一条龙）

> 教师输入：*"请对《一元二次方程》做一次章节小测并生成学情报告"*
>
> Agent 自动完成：**识别任务 → 检索知识点（7 个）→ 加载题库（10 题，共 100 分）→ 生成 Word 试卷 + Excel 答题卡 → 加载预置答题（20 名学生）→ 成绩统计 → 学情诊断（A2A 优先，回退本地）→ 生成 PDF 学情报告**，全程 9 个节点、步骤实时可见。

## 3. 智能体互联技术选型

> 本赛道要求基于 AIP 智能体互联国标与官方 ACPs 开源代码实现"注册 / 发现 / 互联 / 跨端访问"的完整闭环。本项目在不破坏现有教学业务闭环的前提下，通过一个独立的 `backend/interop/` 适配层把业务能力翻译成 ACPs 协议语义——**业务层不变，协议层外挂**。

### 3.1 协议与官方 SDK

- 采用官方 **`acps-sdk==2.2.0`**。仓库 `requirements.txt` 锁定该版本；本地安装发行版为 `2.2.0`（其 `acps_sdk.__version__` 常量未随 wheel 同步，仍为 `"2.0.0"`，属 SDK 自身常量滞后，功能以发行版 `2.2.0` 为准）。
- SDK 五件套与本项目适配层的对应关系：

| 协议 | SDK 模块 | 本项目适配模块 | 职责 |
|---|---|---|---|
| AIC | `acps_sdk.aic` | `interop/aic_util.py` | 身份码解析/校验 |
| ACS | `acps_sdk.acs.models` | `interop/acs_builder.py` | 能力描述构建与校验 |
| ADP | `acps_sdk.adp.models` | `interop/discovery.py` | 发现协议客户端 |
| AIP | `acps_sdk.aip` | `interop/aip_server.py` / `rpc_client.py` / `agent_caller.py` | 交互协议（RPC） |
| AMP | `acps_sdk.amp.models` | `interop/amp.py` / `models.py` | 监控日志 |

### 3.2 角色定位

EduMate-AIP 的定位是 **AIP Partner**（能力提供者）：接收 Leader 的 `TaskCommand`，执行教学任务，返回 `TaskResult`（状态 + 产出物）。同时它也是一个 **AIP Leader 客户端**：在学情诊断节点，通过 Discovery → Agent Selection → RPC 调用外部诊断 Agent，聚合结果后回写业务。

### 3.3 AIC 身份码

- 10 级点分结构：`1.2.156.3088`（OID 前缀，1–4 级）`. 版本(第5级) . ARSP(6) . Vendor(7) . Ontology SN(8) . Instance SN(9) . CRC(10)`。
- 第 1–4 级纯数字；第 5–10 级为 Base36；第 10 级为 4 位 CRC（CRC-16/CCITT-FALSE，poly=0x1021，init=0xFFFF，需 ARSP 内部 SALT 才可完整校验，SALT 不公开）。
- 示例（合成，仅示意结构）：`1.2.156.3088.1.ABC.XYZ.12345.0000.ABCD`。真实 AIC 由平台注册审核后分配，写入 `.env` 的 `ACP_AIC`，不入库、不硬编码。

### 3.4 能力描述 ACS

`interop/acs_builder.py` 构建符合 `AgentCapabilitySpec`（`protocolVersion="02.02"`）的 ACS，关键字段：

- `name="EduMate-AIP"`、`version="1.0.0"`；
- `provider.organization="EduMate 项目组"`（不含学校/指导教师信息）；
- `securitySchemes.mtls`（mutualTLS）；
- `endPoints`：`transport="JSONRPC"`，`url={service_base_url}/rpc`；
- `skills`：三条教学技能 `edumate.exam-loop` / `edumate.question-gen` / `edumate.lesson-plan`。

### 3.5 发现协议 ADP 与智能体选择

- 发现端点：`POST {discovery_base_url}/acps-adp-v2/discover`（默认 `https://wt.ioa.pub/discovery`），带 mTLS 客户端证书与 trust bundle。
- `interop/discovery.py` 构造 `type="explicit"` 请求，解析 `result.acsMap{AIC→ACS}` 与 `result.agents[].agentSkills[]`，提取候选 `(aic, acs, group)` 三元组。
- `interop/orchestrator.py` 的 `select_candidate()` 按下述合规条件选择第一个候选：**AIC 为合法 10 段结构** 且 **ACS 中存在 `https://` 端点**。

### 3.6 AIP 交互协议

- 走 JSON-RPC 2.0：`POST /rpc`，`method="rpc"`，`params.command` 为 `TaskCommand`。
- `TaskState`：`accepted / working / awaiting-input / awaiting-completion / completed / canceled / failed / rejected`。
- `interop/aip_server.py` 委托官方 `handle_rpc_request` + `CommandHandlers` 处理 `start`（执行工作流）与 `get`（返回快照）；`cancel/continue/complete` 复用 SDK 语义。
- 客户端 `interop/rpc_client.py` 用官方 `AipRpcClient` 发起 `start_task`，`interop/agent_caller.py` 封装同步/异步调用。

### 3.7 mTLS 与身份绑定（identity binding）

- **客户端 mTLS**（`rpc_client.py`）：构建 `ssl.SSLContext`，`CERT_REQUIRED`，加载本方 client 证书 + 私钥 + 自定义 CA bundle + 系统默认证书，用于出站 discover/RPC 请求。
- **服务端 mTLS**（`serve_mtls.py`）：独立的 AIP 进程入口，Uvicorn 直连 `0.0.0.0:9443` 自终止 TLS（`PROTOCOL_TLS_SERVER`、`CERT_REQUIRED`、`minimum_version=TLSv1_2`），并用官方 `AipPeerCertH11Protocol` 提取对端证书供身份绑定。
- **身份绑定**：`identity_binding_resolved = identity_binding_enabled ∧ mtls_server_enabled ∧ 已配置 aic ∧ 已配置三项证书`。满足时才向官方 `handle_rpc_request` 传入非空 `local_aic` 与 `identity_binding_enabled=True`；否则自动关闭，避免 SDK 报错。
- **当前状态**：代码层已完整接线（客户端 `AipRpcClient(identity_binding_enabled=…)`、服务端 `handle_rpc_request(local_aic=…, identity_binding_enabled=…)`），并有离线单测覆盖。但 mTLS 证书须由梧桐平台 CA 签发，**真实双向认证尚未与平台联调**（见 §5 测试验证）。

### 3.8 AMP 监控日志

- 构造 `message` / `access` 两类记录；关键不变量：`correlation_id = session_id`，同一条消息 send/receive 两侧共享 `messageId`。
- P0 采用本地 JSON-lines sink（`logs/amp.jsonl`）留档；Kafka/TLS 上报在 P1 接入官方 emitter，未配置时明确报错而非静默。

## 4. 系统实现

### 4.1 系统整体架构

```
                        梧桐智能体互联平台 (wt.ioa.pub)
     registry-server(注册)   discovery(发现)   ca-server(证书)   mq/monitor
          ▲ 注册/审核/取AIC/签证书                 ▲ discover/RPC/AMP
          │(人工，平台操作)                        │(运行时，mTLS)
   ┌──────┴────────────────────────────────────────┴──────────┐
   │                     EduMate-AIP 运行时                     │
   │                                                            │
   │  ┌──────────────────── interop 适配层 ──────────────────┐  │
   │  │ aic_util / acs_builder / models / amp                 │  │
   │  │ discovery(ADP) / rpc_client(mTLS) / agent_caller      │  │
   │  │ orchestrator(Discovery→Selection→RPC→Parse)            │  │
   │  │ aip_server(Partner /rpc+/health) / serve_mtls(9443)    │  │
   │  └──────────────────────────┬────────────────────────────┘  │
   │                             │ TaskCommand ⇄ TaskResult        │
   │  ┌──────────────────────────▼────────────────────────────┐  │
   │  │  现有业务层（不变）                                    │  │
   │  │  API(chat/tasks/health)                                │  │
   │  │  Agent 引擎：Planner → Workflow → Executor → ToolRegistry│  │
   │  │  文档服务：exam_docx/answer_sheet/score_analysis/       │  │
   │  │           report_pdf/lesson_plan/preview                │  │
   │  └──────────────────────────┬────────────────────────────┘  │
   └─────────────────────────────┼───────────────────────────────┘
                                 ▼
   浏览器(前端 3 栏工作台)     本地文件系统：data/ 种子数据 + data/outputs/ 产物
```

要点：单体进程承载 API、Agent、工具、静态资源与 AIP `/rpc`（`ACP_ENABLED=true` 时挂载）；无数据库、无队列、无容器。

### 4.2 Agent 引擎

| 组件 | 职责 | 是否调用 LLM |
|---|---|---|
| **Planner** | 解析用户意图，选择工作流并提取参数（学科/章节/题量等） | ✅（1 次，含关键词兜底） |
| **Workflow** | 预定义步骤序列，编排节点、传递中间产物 | ❌（纯编排） |
| **Executor** | 单工具调用薄封装，校验工具返回 | ❌（不自主选工具） |
| **Context** | 任务状态容器：参数、步骤事件、产物清单 | ❌ |

**设计要点**：采用「**预定义工作流 + 节点内单工具调用**」模型。工作流决定"做哪几步"（稳定、可预期）；节点内由工作流**显式指定**要调用的工具，而非让 LLM 自主决定调用序列——避免自由 ReAct 的跑飞/死循环风险。LLM 工具内部的传输重试与结构化校验重试由 `llm_utils.structured_completion` 承担。

### 4.3 工作流（Workflow）

三个工作流由 Python 函数按固定顺序组成，任一节点失败即中止（fail-fast），并受全局超时上限约束（`WORKFLOW_TIMEOUT = 180s`）。

**`exam_loop`（章节小测一条龙，9 节点）**：

```
① understand_task      — Planner 解析任务 → 选定工作流 + 提取参数
② fetch_knowledge      — 调 search_knowledge_points 检索知识点
③ generate_exam        — 加载种子题库（确定性，保证与成绩分析一致）
④ build_exam_docx      — 生成 01_试卷.docx
⑤ build_answer_sheet   — 生成 02_答题卡.xlsx
⑥ load_student_answers — 加载预置答题（seed）
⑦ analyze_scores       — pandas 确定性统计
⑧ diagnose             — A2A 诊断（Discovery→RPC 调外部 Agent，失败回退本地 generate_diagnosis）
⑨ build_report_pdf     — 生成 03_学情报告.pdf
```

**`question_gen`（智能组卷，5 节点）**：`understand_task → fetch_knowledge → generate_exam（LLM 实时出题）→ build_exam_docx → build_answer_sheet`。

**`lesson_plan`（AI 教案，3 节点）**：`understand_task → generate_lesson_plan_content（LLM）→ build_lesson_plan_docx`。

每个节点结束写一条步骤事件（SSE 推送），前端时间线实时更新。

### 4.4 LLM 调用方案

- **抽象层**：`LLMService`（业务入口）→ `LLMProvider`（抽象）→ `DeepSeekProvider`（OpenAI 兼容实现）。业务层不直接依赖厂商。
- **默认模型**：`deepseek-v4-flash`（`DEEPSEEK_BASE_URL=https://api.deepseek.com`，`LLM_TIMEOUT=60s`）。
- **结构化输出**：不依赖 LLM 直接吐 JSON 文本，而是用工具调用返回结构化参数——为每个结构化输出合成一个 `submit_*` 工具，模型以工具调用提交结果，Pydantic schema 校验。
- **重试**（`llm_utils.structured_completion`）：
  - 传输层：LLM 超时/网络/限流，指数退避重试 2 次；
  - 校验层：结构化输出不符合 schema，把校验错误回喂模型，最多 3 次尝试。
- DeepSeek 思考模式不支持强制 `tool_choice={"type":"function",...}`（会报 400），故使用 `tool_choice="auto"` + 系统提示词要求调用工具 + 纯 JSON 文本兜底解析。

### 4.5 Tool 调用架构

统一工具接口：`name + description + parameters(JSON Schema) + handler(params)`；`ToolRegistry` 提供 `get_schemas()`（供 LLM）与 `execute(name, params)`（校验 + 执行 + 结构化错误回喂）。

**两类能力明确区分**：

| 类别 | 工具 | 调用方式 |
|---|---|---|
| LLM 面向工具（3 个） | `search_knowledge_points`（确定性检索）<br>`generate_questions`（LLM 出题）<br>`generate_diagnosis`（LLM 诊断） | 注册进注册表，可被调用 |
| 确定性文档服务（4 个） | `create_exam_docx`<br>`create_answer_sheet_xlsx`<br>`create_report_pdf`<br>`create_lesson_plan_docx` | 不进注册表，由工作流确定性调用，LLM 拿不到其 schema |

### 4.6 文档服务

| 产物 | 库 | 方案 |
|---|---|---|
| 试卷.docx | python-docx | 统一样式函数，题干与答案分离 |
| 答题卡.xlsx | openpyxl | 表头 + 题号列 + 姓名列 + 每题分值 |
| 学情报告.pdf | reportlab | 表格 + 柱状图（内置图形，不引入 matplotlib） |
| 教案.docx | python-docx | 结构化段落（目标/重难点/过程/作业） |
| HTML 预览页 | Jinja2 | 同一份数据渲染为 HTML，供前端 iframe 预览 |

**关键约定**：文档服务接收"数据 + 结构"，样式由服务端统一控制；LLM 只负责"内容"，不负责"排版"。

### 4.7 数据层

- 三份种子数据（确定性数据源，启动时 `knowledge/loader.py` 校验 + 缓存）：
  - `data/knowledge/knowledge_points.json`：知识点 **7 个**（含层级/描述/典型题型）；
  - `data/questions/question_bank.json`：规范测验 **10 题、共 100 分**（每题关联知识点 ID）；
  - `data/demo/student_answers.json`：预置答题 **20 名学生**（逐题得分 + 总分）。
- 产物统一存 `data/outputs/{task_id}/`，命名 `{序号}_{类型}.{ext}`。
- 无数据库：任务元数据保存在内存 `TaskStore`（含并发锁）。
- 路径安全：所有文件路径由后端生成，只取文件名 `basename`，不接受前端传绝对路径，杜绝路径穿越。

### 4.8 智能体互联实现（interop 适配层）

| 模块 | 职责 |
|---|---|
| `aic_util.py` | AIC 10 级结构解析/校验、Base36、CRC-16/CCITT-FALSE（需 SALT 才校验 CRC）、本体/实体判定 |
| `models.py` | 对已核实 schema 的忠实复刻：AIP（`TaskState`/`TaskCommand`/`TaskResult`/`RpcRequest`/`RpcResponse`）+ AMP（`LogRecord`/`MessageBody`/`AccessBody`），线格式 camelCase |
| `acs_builder.py` | 构建 ACS（`02.02`、3 skill、mTLS JSONRPC 端点）+ `validate_acs` + 可选 SDK 二次校验 + `write_acs` |
| `discovery.py` | ADP 发现客户端（httpx 真实请求，无本地假实现） |
| `rpc_client.py` | mTLS RPC 客户端工厂（`AipRpcClient` + SSLContext + identity binding） |
| `agent_caller.py` | 同步/异步 `call_agent` 封装 |
| `result_parser.py` | `TaskResult` → 结构化 dict（taskId/status/products/products_text） |
| `orchestrator.py` | 完整 Discovery → Selection → RPC → Parse 管线（`orchestrate` / `orchestrate_sync`） |
| `aip_server.py` | Partner 端点 `POST /rpc` + `GET /health`（委托官方 SDK，产物映射为 `Product[]`） |
| `serve_mtls.py` | AIP mTLS 专用 Uvicorn 入口（`0.0.0.0:9443`） |
| `amp.py` | AMP 日志构造 + 本地 JSON-lines sink + `AmpEmitter` |
| `config.py` | ACP 配置读取（env 优先，全部可选） |

**A2A 诊断节点（`_a2a_diagnose`）执行流程**：

```
成绩统计(stats + 薄弱知识点)
        ↓ 构造结构化协作 query
orchestrate_sync(query, timeout=5.0, verify=trust_bundle)
        ↓
   Discovery → select_candidate → call_agent(mTLS RPC) → parse_task_result
        ↓
成功(status∈completed/success 且有 products_text)
        → diagnosis={"source":"a2a_external_agent", content, local_fallback=false}
        ↓ 失败(任何异常)
        → 记录 a2a_metadata{fallback_used:true, error}
        → 回退本地 generate_diagnosis（不中断工作流）
        ↓ 本地也失败
        → 降级兜底 diagnosis（保证报告 schema 仍可生成）
```

无论成功/失败/双失败，均把 `a2a_metadata`（enabled/fallback_used/error/task_id/partner_aic）写入 `ctx.params`，供审计追溯。

### 4.9 前端

- **技术栈**：原生 HTML/CSS/JavaScript，无框架、无构建；由 FastAPI `StaticFiles` 挂载 `frontend/`。
- **页面形态**：三栏「教师 AI 工作台」——左侧导航（工作台/智能任务/学情分析/教学方案/Agent 协作/任务记录/设置）+ 主工作区（欢迎区、任务输入 Composer、当前任务时间线、学情分析 Dashboard、教学方案、Agent 协作网络、设置）+ 右侧信息栏（系统状态、当前任务）。
- **实时通信**：原生 `EventSource` 消费 SSE（`GET /api/tasks/{id}/events`），断线自动重连；`GET /api/tasks/{id}` 轮询兜底。
- **核心前端函数**：`checkHealth`（健康检查）、`sendChat`（AI 对话）、`submitTask`（提交任务）、`streamEvents`（SSE 流）、`pollTask`（轮询兜底）、`applySnapshot`（渲染快照）、`renderResultPanel`（渲染产物面板）。
- **预览**：PDF 用 `<iframe>` 原生渲染；Word/Excel 由服务端 Jinja2 渲染 HTML 预览页后 `<iframe>` 展示。

## 6. 应用价值

1. **减负增效**：把教师从出卷、批改统计、报告排版等文档机械劳动中解放出来，回归教学本身。
2. **智慧教育的可落地落点**：不只输出分数，而是定位「薄弱知识点 + 分层教学建议」，服务因材施教。
3. **从聊天到执行**：交付真实、可编辑、带格式的文档文件，而非文字答案；一次任务产出互相关联的多份文件（试卷↔答题卡↔报告）。
4. **智能体互联价值**：EduMate 不是孤立模型，而是可被 Leader/平台发现、调用、跨端访问的标准化 AIP Partner；学情诊断还可反向调用外部诊断 Agent，体现"智能体协作"的赛道主题。
5. **过程透明可信**：每一步执行可观测、可中断、失败可读，增强教师信任与答辩表现力。

### 8.2 种子数据字段与关联关系

| 文件 | 关键字段 | 关联 |
|---|---|---|
| `knowledge_points.json` | `kp_id` / `name` / `level` / `section` / `description` / `typical_types` | 被题目 `knowledge_points[]` 引用 |
| `question_bank.json` | `question_id` / `type` / `stem` / `options` / `answer` / `score` / `difficulty` / `knowledge_points[]` / `analysis` | 被答题 `question_scores` 键引用 |
| `student_answers.json` | `student_id` / `name` / `question_scores{}` / `total` | `quiz_id` 与题库一致，`total = Σ question_scores` |

约束：题目 `knowledge_points` 值必须存在于知识点文件；答题 `question_scores` 键集合 = 题库 `question_id` 集合，且每题得分 ≤ 该题 `score`；`total` 为各题得分求和。
