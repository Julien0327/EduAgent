## 0. 文档地位与变更控制（防漂移机制）

本文档与《技术方案 v2.1》是项目打磨期的**唯一产品目标基准**，服务于一个明确目的：**执行过程可能跨多个会话、上下文可能被压缩，任何偏离都必须落到文档，而不是依赖记忆。**

规则（对每一轮执行生效）：

1. **开工必读**：任何会话开始改代码前，先完整阅读本文件与《技术方案 v2.1》。
2. **变更三步**：执行中要偏离目标（新增/砍掉/改设计）时，必须 ① 在本文件 §10「变更记录」追加条目（日期、内容、理由、影响的功能与验收指标）；② 同步修改受影响的章节；③ 《技术方案》若受影响同步改。**禁止只改代码不改文档。**
3. **状态标记**：`【已定】`= 已经确认不可再议；`【待确认·默认推荐】`= 按推荐方案执行，用户可推翻；`【待回填】`= 执行产生实测数字后回填。
4. **验收即真相**：每个功能与里程碑的验收标准写在文档里，完成与否以验收结果为准，不以"感觉做完了"为准；**计划实现的功能不写成已有能力，设计目标不写成实测结果。**

## 1. 背景与目标

### 1.1 项目现状基线（2026-11-08 全项目逐文件审计；2026-11-10 git 三点同步后刷新 + 终审核对）

**已实现且可靠（保留为资产）**：

- 三条教学工作流闭环（exam_loop / question_gen / lesson_plan），手写 Plan-and-Execute 引擎（Planner→Workflow→Executor，零重型框架）
- AIP 国标智能体互联层 `backend/interop/`（**2089 行**有效代码：AIC/ACS/ADP/AIP/AMP + mTLS + identity binding + **AMP 心跳与访问日志**），已接入 exam_loop 诊断节点（A2A 优先、本地回退）
- 可靠性工程：LLM 超时/重试、全局工作流超时、fail-fast 种子校验、SSE 断线回退轮询、路径穿越防护
- **98 个测试函数**（11 个文件）；已部署阿里云 2核2G，域名公网可访问（服务器 2027-10 到期）

**硬伤（本次升级对象）**：

| # | 问题 | 现状值 |
|---|---|---|
| H1 | 数据 demo 规模 | 7 个知识点 / 10 道题 / 20 名学生 |
| H2 | 检索原始 | JSON 关键词匹配，无向量、无重排 |
| H3 | 无引用溯源 | 试卷/教案/报告不标内容来源 |
| H4 | 无评测体系 | 质量与正确性无任何数字 |
| H5 | 无业务 Trace | 有日志，无步骤级 token/耗时/输入输出快照 |
| H6 | 任务内存态 | 重启丢任务，无会话与多轮记忆 |
| H7 | 诊断浅 | 仅"正确率<0.6 标红"，无根因归因 |
| H8 | API 无认证与限流 | 7 个端点全部匿名可调（公网可达），任务提交/文件下载无保护 |
| H9 | 无学生数据通道 | 学情数据仅有 demo 种子（20 名学生），无真实数据导入入口 |

### 1.2 升级目标（一句话）

**从「竞赛 demo」升级为「生产系统的微缩景观」**——数据工程、可信检索、可解释诊断、可观测、评测体系、多智能体六个器官全部做到「小而真」，**每个器官有可复述的数字**。

### 1.3 成功定义（总验收，六器官）

| 器官 | 验收信号（达标线） |
|---|---|
| 数据工程 | 知识点 ≥300（初中全量）、题库 ≥2 万、打标抽检合格率 ≥90%；**学生/考试/逐题答题数据经 F16 导入可复现入库** |
| 检索 | 标注查询 recall@5 ≥80%、MRR ≥0.6（目标阈值，实测回填），引用覆盖率 100% |
| 诊断 | 10 例预设根因案例归因一致率 ≥80%；**诊断输入为导入的真实数据，数据不足明确提示"证据不足"** |
| 评测 | 全部指标有 baseline→final 数字；judge–人工一致率 ≥80% |
| 可观测 | Trace 覆盖 100% 工作流步骤；单任务成本与 p95 延迟可见 |
| 多智能体 | 质检环拦截率与回流收敛轮次有数字；A2A 保留可用；MCP 能力开放可用（3 工具可被发现调用，远程访问受认证保护） |

### 1.4 本版产品决策的准绳

本项目的隐性读者是 **AI 应用开发岗位的面试官**。产品决策一律以「真实可用的教学工具」为准绳：优先做教学场景里真实成立的能力（题库、引用、归因、成本可见），不做演示花活；每个能力必须能回答"为什么这么做、效果怎么度量"。

**术语命名纪律（2026-11-10 定）**：对外表述只使用准确、能被追问三层的行业术语（RAG、Critique Agent、A2A、MCP 等）；禁止为凸显技术栈而堆砌流行词、制造花哨概念——每个写出来的词都必须有对应实现；**不将未完成的实践写成简历成果**。

## 2. 产品定位（v2.1）

**面向教师的"教学任务自动化智能体"——教育场景的多智能体工作流引擎：自然语言下达教学任务，系统经混合检索选题、质检复核、文档生成、图谱归因诊断，全程引用可溯源、步骤可回放，产出可直接使用的教学文档（试卷 / 答题卡 / 学情报告 / 教案），班级学情数据经 Excel 模板导入，并可通过 AIP 国标与 MCP 协议对外开放能力、与其他智能体互联。**

定位边界（不是什么）：

- ❌ 不是通用 AI 聊天（以"执行任务 + 交付文件"为目标）
- ❌ 不是泛化 AI Office（不追求万能文档处理）
- ❌ 不是"套壳生成器"——检索、引用、归因、评测是系统的骨架，LLM 只在单步生成与叙述化上发力
- ❌ 不引入重型框架（LangChain/CrewAI/Redis/消息队列/前端框架/微服务），**Agent 编排引擎保持手写**（LangGraph 不进入本项目范围——不进生产路径、不列为开发任务与验收，仅为核心阶段完成后的个人学习项【技术方案 §14 决策⑧】）
- ✅ 是"教育领域数据 + 混合检索 + Agent 编排 + 可信工程"的垂直智能体

**与 v0.1 的差异**：v0.1 按"比赛 5 天 MVP"设计；v2.0/v2.1 按"生产微缩景观"设计。v0.1 中"文档读取（read_xlsx/pdf）""学生端在线作答""多模态 OCR"等设想**正式移入范围外**（见 §7）；v0.1 设想的 React/Vue 前端确认**不采用**（保持原生三件套）。

## 3. 目标用户与痛点

| 用户 | 优先级 | 说明 |
|---|---|---|
| 一线中小学教师（主科：数/语/英） | ★★★ 核心 | 出题/批改/统计/报告每周 5–10 小时 |
| 教研组 / 年级组 | ★★ | 统一命题、组卷、考后统一分析 |
| 教培机构教师 | ★★ | 出题 + 个性化反馈报告 |

痛点（继承 v0.1 四条 + v2.0/v2.1 新增两条）：

1. 出题耗时：手动组卷 30–60 分钟/套，还要排版、评分标准、答题卡。
2. 成绩统计繁琐：Excel 公式算平均分/及格率/优秀率，重复劳动。
3. 学情分析难：只知道分数，不知道"哪个知识点没掌握、根因在哪、该补什么"。
4. 文档格式劳动：分析结果做成 Word/PDF 报告要大量排版时间。
5. **AI 产出不可信**：通用 AI 出的题对不对、覆盖全不全、内容有没有依据，教师无从核验——**引用溯源与质检复核正是对这一痛点的直接回答**。
6. **【v2.1】学情数据散落在成绩登记 Excel 里**：教师手里有逐题得分，却没有工具把它变成"每个学生缺什么、该补什么"——**F16 Excel 导入 + F7 归因正是对这一痛点的直接回答**。

### 4.2 各功能规格

> 统一格式：**用户故事 → 行为规格 → 边界与错误 → 验收**。

**F1 多轮对话与任务理解**
- 故事：教师描述模糊时，系统追问而不是猜。
- 行为：对话以会话（session）为单位多轮进行；任务理解（意图+参数：学科/章节/题量/总分/难度/题型）在信息不足或冲突时生成一个澄清问题（每任务至多 2 轮追问，超限按默认值执行并在结果中注明）；会话与消息落库。
- 边界：超长输入截断策略见技术方案 §7.2；追问逻辑失败不得阻塞任务（降级为按默认值执行）。
- 验收：golden set 中模糊用例的追问/降级行为符合预期；重启后会话可恢复。

**F2 知识检索与引用（RAG）**
- 故事：教师说"二次函数"这类口语表达，系统能找到对应知识点，并告诉依据。
- 行为：检索分两步——**先"找知识点"**（FTS5 关键词 + 本地 bge 向量双路召回，分数各自归一化后融合重排），**再"找题"**（由知识点经题目关联扩展候选，按学段/难度/题型等结构化条件过滤，独立评分重排）——两个阶段的分数不直接混合（技术方案 §4.2 三阶段）；检索结果全部携带知识点 ID 作为引用。
- 边界：检索无结果时明确返回"无匹配知识点"并列出相近候选，不静默空转。
- 验收：50 条标注查询 recall@5 ≥80%、MRR ≥0.6（目标阈值，实测回填）；引用覆盖率 100%。

**F3 智能组卷 · 题库问数（受限域 NL2SQL）**
- 故事："出 5 道中等难度的二次函数应用题，满分 40"→ 系统从真实题库检索组卷，而不是从 10 道种子题里选。
- 行为：任务参数 → 知识点召回 → 题目候选扩展（知识点关联 + 结构化过滤）→ 题目独立重排 → 分值配平（按题型权重贪心配平到目标总分）→ 组卷；试卷每题带 [题库ID] 引用（页脚注明来源构成）；全部为参数化查询，禁止拼接 SQL。
- 边界：候选不足时如实报告缺口（"符合条件题目仅 3 道，缺 2 道"）并给出放宽建议；不降低难度凑数。
- 验收：组卷结果的题目数/总分/难度分布与参数一致率 ≥95%；引用完整。

**F4 质检复核环（Critique Agent）**【决策③·已定】
- 故事：LLM 生成的内容先过一道独立质检，不合格不交付。
- 行为：生成题目 → 质检 agent 三维校验（正确性：答案自洽；难度复核：与标注难度一致；查重：与题库相似度）→ 不合格回流重生成（至多 2 轮，仍不合格则剔除并报告）；质检结论进 Trace。
- 边界：质检 agent 不可用时不阻塞主流程（记 warning，人工抽检兜底）。
- 验收：拦截率、回流收敛轮次有数字；被剔除题目在任务结果中可追溯。

**F5 答题卡生成**
- 行为：保留现有 openpyxl 答题卡（表头/题号/分值/标准答案），新增与试卷题号一致的引用页脚。
- 验收：题号-分值-标准答案与选中题目集完全一致。

**F6 成绩统计**
- 行为：保留 pandas 统计（平均/最高/最低/中位数/及格率/优秀率/分数段/逐题正确率/薄弱知识点排序）。
- 验收：与现有实现对齐（回归测试保护）。

**F7 学情根因归因（新增核心能力）**
- 故事："二次函数薄弱"不是终点——系统沿知识图谱回溯，指出"根因：一次函数图像平移不熟"，并推荐补练题目。
- 行为：**数据来源 = F16 导入的真实班级/考试/逐题答题数据**（技术方案 §5.1）→ 逐生知识点掌握度 → 薄弱点集合 → 沿前置依赖边回溯至根因 → 归因链（规则引擎，确定性）→ 推荐练习（按根因知识点从题库检索）；规则出骨架，LLM 仅做可读化叙述；输出标注数据范围（考试数/题目数/学生数）。
- 边界：**无导入数据或样本不足（<3 题）时明确返回"证据不足"并说明原因，不强行归因，不以 demo/模拟数据或模型推测冒充真实学情结论**；图谱无前置边时归因链退化为单节点薄弱点。
- 验收：10 例预设根因案例一致率 ≥80%（仅评测用）；以导入的真实班级数据（≥1 班 ≥1 考试）跑通端到端归因；每个归因链可点开看证据（哪些题、正确率）。

**F8 学情报告 PDF**
- 行为：保留 reportlab 报告骨架（班级统计/分数段柱状图/薄弱知识点表），新增：归因链章节（每人或共性）、推荐练习清单、引用页脚（知识点 ID）。
- 验收：报告包含统计+归因+推荐三部分；引用页脚完整。

**F9 教案生成**
- 行为：保留五段结构（目标/重难点/过程/作业），过程与重难点段落标注知识点引用；作业环节可挂接推荐练习（与 F7 联动）。
- 验收：引用完整；教案结构回归通过。

**F10 任务 Trace 回放**
- 故事：教师（和面试官）可以逐步回看"系统每一步做了什么、花了多少 token、多少毫秒"。
- 行为：每个工作流步骤落库快照（输入/输出摘要、token、成本、耗时、错误）；前端时间线从"状态点"升级为"可展开回放"（点击步骤查看详情）。
- 边界：摘要截断至 500 字符；Trace 采集失败不得影响任务执行。
- 验收：Trace 覆盖 100% 步骤；任一历史任务可完整回放。

**F11 成本与性能面板**
- 行为：按任务/按天汇总 token 与费用（单价配置化）；任务卡显示本次成本与关键延迟；面板提供近 30 天视图。
- 验收：单任务成本可复算（Σ 步骤成本 = 任务成本）。

**F12 评测报告页（内部）**
- 行为：展示 golden set 规模、任务成功率、参数准确率、recall@k、judge 均分与校准一致率、p95 延迟等指标的当前值与历史 run 对比；入口放在设置/内部导航。
- 验收：每个指标显示 baseline→current；CI 每次 push 产生 smoke run。

**F13 智能体互联（A2A/AIP）**
- 行为：保留 interop 层与 `/rpc`、mTLS 入口；诊断节点维持"A2A 优先 → 本地回退 → 兜底"三级链路；修复双导入路径隐患（见技术方案 §11.1）。
- 边界：与梧桐平台的真实联调（注册/证书/四步验证）**暂缓**，列为范围外待平台可用时重启。
- 验收：现有 interop 离线测试全绿；A2A 回退链路回归通过。

**F14 任务持久化与会话恢复**
- 行为：tasks/steps/会话/消息全部落 SQLite（替换内存 TaskStore）；服务重启后历史任务、产物、Trace 均可回查。
- 验收：重启后任务回查测试通过；并发提交无数据竞争（WAL 模式）。

**F15 能力开放（MCP Server）**【决策③·已定】
- 故事：其他 AI 客户端（支持 MCP 的助手/智能体）能直接调用 EduAgent 的核心能力——系统的价值不止于自己的前端。
- 行为：官方 MCP Python SDK 实现 3 个工具（`search_knowledge_points` 知识点检索 / `query_question_bank` 题库问数 / `diagnose_learning_gaps` 学情归因），全部复用内部服务层；传输：**本地 stdio + 远程 Streamable HTTP**（技术方案 §8.3）；远程访问启用 Access Token 认证与限流，敏感工具（学情归因，访问学生数据）需显式授权。
- 边界：三个工具不绕过业务服务层的安全校验；不改变内部编排与 REST API。
- 验收：MCP Inspector 可发现并列出 3 工具（含参数 Schema），调用结果与对应 REST 端点一致；正常与异常响应正确；**远程认证失败 401、未授权调用敏感工具被拒绝**；有离线单测。

**F16 学生数据导入（Excel 模板）**【决策⑦·已定】
- 故事：考完试，教师把成绩登记 Excel 按模板整理后上传，系统即拥有结构化的班级、学生、考试与逐题答题数据——学情诊断从此有真实依据。
- 行为：
  1. **模板下载**：系统生成统一工作簿 `edumate_import_template.xlsx`（5 个工作表），支持整簿导入或按单表分开导入。
  2. **导入对象与字段**（* 必填；关联标识：①班级 ②学号 ③考试 ④题号）：

  **工作表 1 · 班级**
  | 字段 | 必填 | 类型 | 含义/约束 |
  |---|---|---|---|
  | name | * | 文本 | 班级名（关联标识①），如"初一（1）班"；同年级同名视为同一班 |
  | grade | * | 整数 | 1–12 |
  | stage |  | 枚举 | primary/junior/senior；缺省按 grade 推断 |
  | school |  | 文本 | 可选；演示/开源数据禁用真实校名 |

  **工作表 2 · 学生**
  | 字段 | 必填 | 类型 | 含义/约束 |
  |---|---|---|---|
  | class_name | * | 文本 | 关联班级① |
  | student_no | * | 文本 | 学号（关联标识②），班内唯一 |
  | name | * | 文本 | 学生姓名 |

  **工作表 3 · 考试**
  | 字段 | 必填 | 类型 | 含义/约束 |
  |---|---|---|---|
  | title | * | 文本 | 考试名（关联标识③），同一工作簿内不得重名 |
  | class_name |  | 文本 | 可空 = 多班联考 |
  | exam_date |  | 日期 | ISO 格式（YYYY-MM-DD） |
  | subject |  | 枚举 | 缺省 math |
  | stage |  | 枚举 | primary/junior/senior |
  | total_score |  | 数值 | 与题目分值合计不一致 → 警告 |

  **工作表 4 · 考试题目**
  | 字段 | 必填 | 类型 | 含义/约束 |
  |---|---|---|---|
  | exam_title | * | 文本 | 关联考试③ |
  | q_no | * | 整数 | 卷面题号（关联标识④），考试内唯一 |
  | q_id |  | 文本 | 题库题 ID，可选（填写则须存在于题库） |
  | kp_names |  | 文本 | 知识点名（顿号分隔）；匹配不上图谱 → 警告 |
  | score | * | 数值 | >0，本题卷面分值 |
  | stem | 条件 | 文本 | q_id 为空时必填（外部题题干快照） |
  | answer | 条件 | 文本 | q_id 为空时必填 |

  **工作表 5 · 答题记录**
  | 字段 | 必填 | 类型 | 含义/约束 |
  |---|---|---|---|
  | exam_title | * | 文本 | 关联考试③ |
  | class_name | * | 文本 | 关联班级① |
  | student_no | * | 文本 | 关联学生② |
  | q_no | * | 整数 | 关联该考试题目④ |
  | score | * | 数值 | 0 ≤ 得分 ≤ 该题卷面分值 |
  | is_correct |  | 枚举 | 对/错/0/1；主观题可空 |

  3. **数据校验**：必填/类型/枚举/范围校验；四级关联校验（①班级→②学生→③考试→④题目 逐级定位）；完整性校验（每考试 ≥1 题；total_score 与分值合计）；重复识别（批内重复行 + 库内唯一约束预检）。校验不通过的行**不写入业务表**。
  4. **错误报告**：定位到工作表/行号/字段，含错误码与原因（如 `E_REF：工作表[答题记录] 第 12 行 student_no=S2026 未在工作表[学生]中找到`）；**区分 error（该行不写入）与 warning（写入并标注）**；报告可下载，供修正后重传。
  5. **重复导入**：批次指纹（导入类型 + 文件 SHA-256）命中已导入批次 → 默认拒绝并返回原批次报告；答题记录支持显式覆盖重导（事务内先删该考试原记录再写入，前端二次确认）；数据库层唯一约束兜底——**杜绝答题记录重复累计**。
  6. **导入流程**：解析 → 字段映射 → 格式校验 → 关联校验 → 重复检测 → 事务写入 → 结果报告（技术方案 §3.4 七步管线；不可恢复错误整批回滚，行级错误按 partial 如实报告，导入中禁止并发导入）。
- 边界：不做在线作答/批改回收（§7）；单批上限 5000 行（`IMPORT_BATCH_MAX_ROWS` 可调）；**F7 学情诊断只认导入数据**——demo 种子数据仅限开发评测环境且输出明确标注，数据不足返回"证据不足"而非推测结论。
- 验收：五类用例全过（合法导入 / 含错文件→报告准确定位 / 重复导入拒绝 / 覆盖重导 / 中断回滚后无部分写入）；错误报告定位精度 100%（sheet/行/字段）。

### 4.3 引用与溯源规范（产品级约定）

1. **必须带引用的内容**：试卷每道题（题库ID）、教案与报告中的知识点论断（知识点ID）、推荐练习（题库ID）。
2. **不需要引用的内容**：纯统计数字（源自成绩数据本身）、通用教学建议措辞。
3. **呈现形式**：文档内为 `[KP:kp_quad_02]` / `[Q:q_00317]` 页脚或行内标注；前端产物卡片提供"查看引用"面板，点击列出全部引用并可跳转知识点详情。
4. **完整性判定**：引用覆盖率 = 应引用字段中实际携带引用的比例，目标 100%。

## 7. 范围守卫（明确不做）

| 不做 | 理由 |
|---|---|
| 用户注册/登录/完整 RBAC 权限体系 | 单教师演示场景；以**轻量 API Access Token + 限流**替代【决策⑧】 |
| 学生端在线作答、OCR 手写批改 | 依赖多模态与回收系统，范围失控；**学生学情数据经 Excel 模板导入（F16）满足诊断需求** |
| 多学科内容生产（物理/化学题库等） | 架构留口子（schema 不绑学科），内容只做数学【决策②】 |
| 开放域 NL2SQL（任意数据库问数） | 只做受限域题库问数；开放域是另一个项目量级 |
| 移动端原生 App、实时协作、K8s/微服务化 | 与目标不符或过度设计 |
| 商用计费、多租户 | 非本项目语境 |
| 梧桐平台真实联调（注册/证书/四步验证） | 依赖外部平台审核流程，**暂缓**非放弃（F13 代码保留） |
| **引入 LangGraph（含对比实验）** | 手写引擎是核心资产与深度来源；LangGraph **不进入本项目范围**——不进生产路径、不列为开发任务与验收、不因它增加周期与服务器依赖，仅为核心阶段完成后的个人学习项【技术方案 §14 决策⑧】 |
| 技术博客撰写/发布 | **已取消**【决策④】；技术沉淀以 README、架构设计文档、技术决策记录与代码注释为主 |
