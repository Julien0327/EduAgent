# 《AI 智慧教育智能体》产品设计方案

> 项目：iCAN 第二十届大学生创新创业大赛 · 创新赛道 · 智慧教育
> 形态：可运行的软件系统
> 版本：v0.1（设计阶段，未含代码）
> 前序调研：Hermes-Easy-Office-Suite（仅作思路参考，**不复制源码、不改动其工程**）

---

## 0. 一句话定位

**一个"懂教学、会做文件"的教学任务自动化智能体：教师用自然语言下达教学任务，Agent 自动编排文档处理工具，产出可直接使用的教学文档（试卷 / 答题卡 / 成绩分析 / 学情报告 / 教案）。**

它不是"AI 聊天机器人"，也不是"AI 文档生成器"，而是把两者结合起来的**教学任务执行者**。

## 2. 产品定位

**面向教师的"教学任务自动化智能体"。**

- **角色**：教师的教学助理（AI 助教），不是工具库。
- **交互**：自然语言任务下达 + 文件上传 → 自动多步执行 → 产出成型的、可继续编辑的文档文件。
- **领域壁垒**：内置学科知识、课程标准、知识点标签与教学专用工具，把"文档处理能力"翻译成"教学动作"（组卷、批改、诊断、出教案）。

定位边界（明确不是什么）：
- ❌ 不是泛化的 AI Office（不追求万能文档处理）
- ❌ 不是通用 AI 聊天（不以"给答案"为目标，而以"执行任务 + 交付文件"为目标）
- ✅ 是"教育场景 + Agent 编排 + 文档工具自动化"的垂直智能体

---

## 3. 目标用户

| 用户 | 优先级 | 说明 |
|---|---|---|
| 一线中小学教师（主科：数/语/英） | ★★★ 核心 | 文档工作最重，出题/批改/统计/报告每周 5–10 小时 |
| 教研组 / 年级组 | ★★ | 统一命题、组卷、考后统一分析 |
| 教培机构教师 | ★★ | 出题 + 个性化反馈报告 |
| 教育管理者 | ★ 次优先 | 成绩汇总、学情报表（后期） |

**核心用户画像**：一位中学数学老师，每周要出 1–2 套小测、批改 2 个班作业、手工在 Excel 里算平均分/及格率、写学情分析——这些都可以交给 Agent。

---

## 4. 用户实际痛点

1. **出题耗时**：手动组卷 30–60 分钟/套，还要排版、配评分标准、做答题卡。
2. **成绩统计繁琐**：Excel 里写公式算平均分/及格率/优秀率/排名，易出错、重复劳动。
3. **学情分析难**：只知道分数，不知道"哪个知识点没掌握、该补什么、怎么分层"。
4. **文档格式劳动**：把分析结果做成 Word/PDF 报告要大量排版时间。
5. **通用 AI 帮不上忙**：ChatGPT 只能"说"答案，**不能直接读懂我的 Excel、也不能产出一份带格式的试卷和报告文件**——这是本项目的直接切入点。

---

## 5. 核心使用场景

1. **单元/课堂小测组卷**（知识点 → 题型 → Word 试卷 + Excel 答题卡）
2. **作业/考试批改 + 成绩录入分析**（读 Excel 成绩表 → 自动统计）
3. **学情分析报告生成**（成绩 + 错题 → 知识点掌握度 → PDF 报告）
4. **教案 / 讲义 / 复习提纲生成**（主题 → Word 文档）
5. **个性化反馈**（针对错题/薄弱知识点，为单个或分组学生生成复习建议）

---

## 6. 产品核心功能

1. **智能组卷**：按章节/知识点、难度、题量、时长，自动出题并生成带格式的 Word 试卷 + Excel 答题卡。
2. **成绩分析**：上传/读入 Excel 成绩表，自动计算统计指标（平均分、及格率、优秀率、分数段、排名）。
3. **学情报告**：把成绩 + 错题知识点结合，生成图文 PDF 学情分析报告（含改进建议）。
4. **教案/讲义生成**：按主题生成结构化的 Word 教案。
5. **多文档联动**：一次任务产出多个**相互关联**的文件（试卷↔答题卡↔报告）。
6. **任务可视化**：Agent 每一步执行过程透明可看（思考、工具调用、产出），增强可信度与答辩表现力。

## 7. 最重要的 Demo 场景

**「章节小测全流程」—— 一条龙教学闭环：**

> 老师输入：*"根据《一元二次方程》给我出一套 20 分钟课堂小测，考完帮我做学情分析。"*
>
> Agent 自动完成：**检索知识点 → 出题 → 生成 Word 试卷 + Excel 答题卡 →（导入学生作答）→ 批改 → 生成学情分析 PDF 报告**。

这个场景贯穿了"理解 → 编排 → 出卷 → 批改 → 诊断"的完整链路，最能同时体现 **Agent 编排能力 + 文档处理能力 + 教育领域知识**，是答辩与路演的绝对主角。

## 8. AI Agent 的工作流程

采用 **Plan-and-Execute + ReAct 混合循环**：

```
用户自然语言任务
      ↓
① 任务理解与拆解（Planner：识别意图 + 拆子任务 + 选工作流）
      ↓
② 领域知识检索（RAG：查知识点、课程标准、题库）
      ↓
③ 工具编排执行（Executor：按需调用文档/分析/领域工具，可多步）
      ↓
④ 产出自检（Validator：格式、完整性、知识点覆盖校验）
      ↓
⑤ 结果交付（生成文件 + 预览 + 摘要），用户审阅后可迭代修改
```

关键设计：**每一步都可观测、可中断、可重试**——这是与"黑盒聊天"的本质区别。

## 9. Tool Calling 架构

统一 **工具注册表 + 标准 Tool 接口**（`name / description / JSON Schema`），由 LLM 根据任务决定调用哪些工具、以什么参数调用。

工具分四类：

| 类别 | 工具 | 说明 |
|---|---|---|
| **文档生成** | `create_docx` / `create_xlsx` / `create_pdf` | 产出试卷、答题卡、教案、报告 |
| **文档读取** | `read_xlsx` / `read_docx` / `read_pdf` / `extract_text` | 解析上传的成绩表、教材、作业 |
| **领域能力** | `search_knowledge_point`（知识点检索）、`generate_questions`（出题）、`analyze_scores`（成绩统计） | 教育专用，是"懂教学"的体现 |
| **文件/任务** | `list_files` / `save_file` / `preview` / `task_status` | 文件管理、预览、进度 |

> 核心原则：**格式由模板保证，内容由 LLM 负责**——工具接收"内容 + 结构 + 模板名"，产出美观稳定、可复用的文档，而不是让 LLM 直接拼排版。

---

## 10. Workflow 架构

采用 **"预定义工作流模板 + 节点内自由 Agent" 的混合架构**：

- **预定义工作流**（稳定、可控、答辩可靠）：组卷流程、成绩分析流程等固定步骤固化下来。
  - 例：`组卷工作流` = 检索知识点 → 出题 → 生成试卷 → 生成答题卡 → 自检
- **节点内自由 Agent**（灵活）：单个节点内部由 LLM 自主决定调用哪些工具、几次调用。

好处：**该稳的地方稳（流程不跑飞），该灵活的地方灵活（单步内容自由发挥）**，5 天内能稳定演示，同时不失 Agent 的"智能感"。

## 11. Excel / Word / PDF 文档处理能力如何作为 Agent Tools

| 格式 | 能力 | 技术选型（MVP 建议） | 作为 Tool 的形态 |
|---|---|---|---|
| **Excel** | 读成绩表、算统计、写答题卡/评分表 | `openpyxl` + `pandas` | `read_xlsx`（→结构化数据）/ `create_xlsx`（数据 + 模板 → 文件） |
| **Word** | 生成带样式的试卷、教案、讲义 | `python-docx`（模板 + 填充） | `create_docx`（内容结构 + 模板 → 文件） |
| **PDF** | 生成学情报告、读取已有文档 | `reportlab` / `weasyprint`；`pdfplumber` | `create_pdf`（图表数据 → 报告）/ `read_pdf` |

**关键设计**：
1. 文档处理**不是裸露的库调用**，而是封装成带 schema 的 Tool，让 LLM 能以"自然语言意图"驱动。
2. **模板驱动**：试卷模板、报告模板、答题卡模板预置好样式，LLM 只填"内容与结构"，保证产出专业、统一、可编辑。
3. **文件即状态**：Agent 的每一步中间产物都落盘为真实文件，可预览、可下载、可继续喂给下一步（多文档联动的基础）。

## 12. 系统整体技术架构

```
┌─────────────────────────────────────────────────────┐
│  前端 (Web)                                          │
│  对话界面 · 文件上传 · 任务步骤可视化 · 文档预览/下载 │
└────────────────────────┬────────────────────────────┘
                         │ REST + SSE/WebSocket
┌────────────────────────▼────────────────────────────┐
│  后端 (Python · FastAPI)                             │
│  接口层 · 会话管理 · 文件存储 · 任务队列              │
│  ┌──────────────────────────────────────────────┐   │
│  │ Agent 引擎                                    │   │
│  │ Planner(拆解) → Executor(工具编排) → Validator │   │
│  └──────────────────────────────────────────────┘   │
│  ┌───────────────┐  ┌──────────────────────────┐     │
│  │ LLM (Claude等) │  │ 工具层：文档工具 + 领域工具 │   │
│  └───────────────┘  │ 知识库(RAG) · 题库 · 模板   │   │
│                     └──────────────────────────┘     │
│  存储：SQLite(元数据) + 文件系统(产物) + 向量库(可选) │
└─────────────────────────────────────────────────────┘
```

**选型理由**：文档处理库（`python-docx` / `openpyxl` / `pandas` / `reportlab`）生态在 Python 最强，后端用 Python 是自然的；LLM 用 Claude（工具调用/Agent 能力成熟）；前端用 React/Vue 提供交互与可视化。

---

## 13. 前后端架构

- **前端**：React（或 Vue3）+ 组件化。核心页面 = 对话任务栏 + 文件/产物面板 + **任务步骤时间线**（可视化 Agent 的每一步）。
- **后端**：FastAPI，分层 = API 层 → Agent 引擎层 → 工具层 → 数据层。
- **通信**：任务执行用 SSE/WebSocket 流式推送步骤进度（让"Agent 正在思考/正在调用工具"可见，是演示的重要加分项）。
- **前后端分离**，接口契约先行，便于并行开发与稳定联调。

---

## 14. 数据流

```
用户输入(自然语言 + 文件上传)
        ↓
前端 → POST /tasks（任务创建）
        ↓
Agent 引擎：Planner 拆解 → 检索知识库 → 调用工具
        ↓
工具产出中间文件（试卷/答题卡/统计结果/报告）
        ↓
产物落盘 → 元数据入 SQLite → 前端订阅 SSE 获取步骤与产物
        ↓
用户预览 / 下载 / 提出修改意见（进入新一轮迭代）
```

## 16. MVP 必须实现的功能（5 天可稳定演示）

**核心闭环（必做）：**

1. **智能组卷**：输入章节/知识点 + 题量/时长 → 生成 Word 试卷 + Excel 答题卡。
2. **成绩分析**：上传 Excel 成绩表 → 自动统计（平均分/及格率/优秀率/分数段）→ 生成学情分析 PDF 报告。
3. **教案生成**：输入主题 → 生成 Word 教案（作为组卷之外的第二个场景，展示"非单一功能"）。
4. **任务可视化**：Agent 步骤流式展示。
5. **文件预览与下载**：产物可直接查看、下载。

**为演示稳定性做的关键决策：**
- **内置一份"知识点 + 题库 + 课程标准"种子数据**，MVP 不依赖外部真实 RAG 也能稳定出题（真实联网检索作为后续增强）。
- **预置文档模板**，保证产出格式专业统一。
- **预准备演示数据**（一份学生成绩 Excel、一套知识点），保证现场 3 分钟不翻车。

## 18. 与普通 AI 聊天工具相比的创新点

1. **从"给答案"到"交付产物"**：聊天工具只能输出文字；本产品**产出真实、可编辑、带格式的文档文件**。
2. **从"单轮对话"到"多步任务执行"**：Agent 自主编排工具、分步执行、中间产物落盘、过程透明可观测。
3. **从"通用"到"懂教学"**：内置知识点、课程标准、出题/批改/诊断等教育专用工具，输出符合教学规范。

---

## 19. 与普通 AI 文档生成工具相比的创新点

1. **从"生成一段文字"到"理解文件 + 多文档联动"**：能读懂上传的 Excel/PDF 内容，一次任务产出**互相关联的多份文档**（试卷↔答题卡↔报告），而非孤立的单文件。
2. **从"模板填空"到"Agent 自主编排"**：不是套死模板，而是根据任务动态决定用哪些工具、几步完成。
3. **从"办公通用"到"教育垂直"**：普通文档工具不懂"知识点覆盖、难度分布、评分标准、学情诊断"这些教学语义，本项目把这些做成了领域能力。

---

## 20. 本项目如何体现"智慧教育"

"智慧"不体现在"会聊天"，而体现在**把教育领域知识做进系统，让自动化真的懂教学**：

1. **学科知识**：内置知识点图谱与课程标准，出题/诊断有据可依。
2. **教学法**：懂题型结构、难度分层、评分标准、课时约束。
3. **学情诊断**：不只看分数，而是定位"薄弱知识点 + 分层建议"，服务"因材施教"。
4. **减负增效**：把教师从文档机械劳动中解放，回归教学本身——这是智慧教育的真正价值落点。

一句话：**用 Agent + 文档自动化，把"经验依赖的教学事务"变成"可自动执行、可诊断、可复用的教学智能"**。

## 21. 3 分钟以内可完整演示的 Demo 设计

**Demo 脚本（约 2 分 40 秒）—— 一条龙教学闭环：**

| 时间 | 环节 | 操作与看点 |
|---|---|---|
| 0:00–0:20 | 开场定位 | 一句话："让老师用一句话完成出卷+批改+学情分析"。打开界面，展示对话栏 |
| 0:20–1:05 | **场景① 智能组卷** | 输入"出一套《一元二次方程》15 分钟课堂小测，10 道题"。Agent 分步展示：检索知识点 → 出题 → 生成 **Word 试卷 + Excel 答题卡**，实时预览并下载 |
| 1:05–2:00 | **场景② 成绩分析** | 上传预准备的成绩 Excel，输入"分析这次测验并出学情报告"。Agent 读 Excel → 算统计 → 生成 **PDF 学情报告**（分数段图、薄弱知识点、改进建议） |
| 2:00–2:25 | **场景③ 个性化反馈** | 输入"给错题最多的学生生成复习建议"。Agent 生成针对性的 Word 建议单（体现"因材施教"） |
| 2:25–2:40 | 收尾升华 | 强调三大创新点：自然语言→多步自动执行→产出可用文档；呼应"智慧教育·减负增效" |

**Demo 稳定性保障：**
- 全部关键数据（成绩 Excel、知识点库、部分题库）**提前预置**，现场零外部依赖。
- 场景②③可拆开作为"备用彩蛋"，若时间不足只演示①②也完整。
- 步骤可视化让评委看到 Agent 的"思考与工具调用"，是区别于竞品的最直观亮点。

## 最终结论（A–F）

### A. 产品定位
面向中小学教师的**"教学任务自动化智能体"（智教助手 EduMate）**——自然语言下达教学任务，Agent 自动编排文档工具，产出试卷/答题卡/成绩分析/学情报告/教案等可直接使用的教学文档。

### B. 核心创新
1. **从聊天到执行**：交付真实可编辑的文档文件，而非文字答案。
2. **多文档联动**：一次任务产出互相关联的多份文件（试卷↔答题卡↔报告）。
3. **教育垂直智能**：内置知识点/课程标准/出题/批改/学情诊断等教学领域能力，而非泛化办公。

### C. MVP 功能
智能组卷（Word 试卷 + Excel 答题卡）、成绩分析（Excel→统计→PDF 学情报告）、教案生成、任务步骤可视化、文件预览下载。核心是**"组卷→批改→学情分析"一条龙闭环**。

### D. 技术架构
React 前端 + Python/FastAPI 后端 + Claude LLM + Agent 引擎（Plan-and-Execute/ReAct）+ 统一 Tool Calling 层（`python-docx`/`openpyxl`/`pandas`/`reportlab` 封装为工具）+ 内置知识点/题库 + 模板驱动文档生成。

### E. Demo 流程
开场定位 → 智能组卷（出卷+答题卡）→ 成绩分析（Excel→PDF 学情报告）→ 个性化反馈 → 收尾升华，全程 ≤3 分钟，数据预置保证稳定。

### F. 后续开发优先级
1. **P0（当前）**：组卷 + 成绩分析 + 教案 + 任务可视化（一条龙闭环）。
2. **P1**：真实 RAG 知识库接入、更多文档模板、公式/图表的更丰富渲染、题目难度与知识点自动配比优化。
3. **P2**：学生在线作答、手写 OCR 批改、题库管理后台、多学科扩展。
4. **P3**：学校教务系统对接、多人协作、多 Agent 协作等（视比赛周期取舍）。
