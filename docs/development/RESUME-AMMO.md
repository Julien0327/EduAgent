# 简历素材清单（持续更新——每个 Phase 关账时回填）

> 目标：2027 寒假 AI 应用开发实习。用途：简历 bullet 源料 + 面试问答弹药。每个素材 = 数字 + 追问点。
> 检验标准：每条素材必须能扛住 3 层"怎么做的/为什么/换你重做会怎样"追问；写不出来数字的缺口当场标记。

## 项目一句话

EduMate：面向初中数学教师的 AI 教学助手——21 万行真实题库地基 + 知识图谱 + 可信检索（引用溯源）+ 智能组卷 + 学情归因，全链路可评测。

## 故事 1：21 万行题库 ETL 与数据质量审计（Phase 1 / Step 4）⭐ 核心差异化

**数字**：原始 210,488 行 → processed 207,858（98.7%）+ rejected 91（可追溯不物理删除）；流式清洗全程 ~18s；FTS5 查询 0.2–0.4ms；SHA-256 门禁 + 幂等全量重建（重跑 2 轮终态逐数一致）。

**核心情节（清洗规则修复）**：初版规则 `\*+` 全量删星号 → 抽样发现 11,032 行（5.24%）合法数学记法被毁（`27*324` 乘号、`cm**3` 指数）→ 重写为精确残留规则（仅 3 行真残留）→ **从原始文件全量重建** → 自写 21 万行独立重放核验器逐行比对 0 差异 → 恢复 11,054 行。教训成句：**"测试全绿 ≠ 数据正确"——29 项单测全过的情况下数据仍是坏的，只有数据层独立核验才能定案。**

**衍生发现**：扫出数据集填空标记 1,684 行（定性为模板而非损坏）、退化占位 585 行、并发现 1 例数据集自身缺陷（1070129：ans/equation 与题干真值 18.9 不一致）——审计报告可复现。

**面试追问点**：为什么流式不整载（210k×内存）；验算怎么做（AST 白名单安全求值）；rejected 为什么入库不删（可追溯）；去重键为什么不含星号。

## 故事 2：LLM 打标管线与 A/B 对照试验（Phase 1 / Step 5）⭐ LLM 工程化叙事

**数字**：DeepSeek-flash；500 题双臂对照实测 **¥2.85**（预估 ¥1.2 缓存态）；A 臂缓存命中率 **91.8%**（固定前缀缓存）vs B 臂 3.5%；单题 ¥0.00217；A 臂主知识点命中 89.8%、难度一致率 98%、合格率 81.6%（90% 放行线未达→治理循环设计，诚实记录）。

**工程机制（每条都是面试点）**：预算三线（¥10 提醒/¥15 暂停/¥20 硬停）+ 组级累计防绕过（台账初始值=历史批次费用之和——重试/续跑/新建批次都无法绕过）；并发原子预留（无缓存最坏口径，缓存命中不作保护前提）；幂等键 (q_id, prompt_version) + 断点续跑；AIMD 并发（429 降并发非升并发）；manifest 分层（运行级入 Git / 逐题明细入 staging）。

**评测设计**：助手盲标 gold → 用户裁决终版（49 confirmed + 1 pending，pending 不进分母）；A/B 双臂同题同模型同 gold；B 臂发现 embedding 召回天花板（recall@10=62%，13.5 字符 KP 描述短文本召回弱）——**用数据否决了"更便宜"的方案**。

**面试追问点**：为什么 A 臂比 B 臂还便宜（前缀缓存 0.04 元/M vs 候选块全 miss）；429 为什么降并发；81.6% 没达标怎么办（错误归因三桶 → prompt v2 消歧规则已实施待重跑）；如何防预算绕过。

## 故事 3：知识标签溯源体系（Phase 1 / Step 2+4+5）

**数字**：初中 303 KP + 374 前置边（课标拆条+人工抽检修正）；小学 82 KP 规则推导（编号冻结、零挂接如实报告 98.2% 覆盖）；规则标签与 LLM 标签双表隔离 + 消费视图（来源列显式）+ KP 定义版本链（kp_registry v1→v2 哈希链）。

**设计原则成句**：规则标签=候选非可信（55% 误挂率实测证据）；LLM 标签绝不继承规则结果（prompt 构造查询零 q_kp JOIN，单测断言）；KP 编号冻结保证跨运行稳定。

**面试追问点**：为什么双表不合并；视图回退逻辑（unmapped 永不回退规则）；KP 定义演进怎么不破坏历史批次（快照哈希落批次表）。
