# 简历素材清单（持续更新——每个 Phase 关账时回填）

> 目标：2027 寒假 AI 应用开发实习。用途：简历 bullet 源料 + 面试问答弹药。每个素材 = 数字 + 追问点。
> 检验标准：每条素材必须能扛住 3 层"怎么做的/为什么/换你重做会怎样"追问；写不出来数字的缺口当场标记。

## 项目一句话

EduMate：面向小学数学教师的 AI 教学助手（2026-11 三大决策收窄为**小学单学段**：82 前置图 / 小学演示数据 / 初中运行时清理）——21 万行真实小学题库地基 + 知识图谱 + 可信检索（引用溯源）+ 智能组卷 + **学情归因（确定性掌握度/前置图根因/真实题库推荐）+ 任务 Trace 与成本可观测 + F16 导入前端页**，全链路可评测、可复现。

## 故事 1：21 万行题库 ETL 与数据质量审计（Phase 1 / Step 4）⭐ 核心差异化

**数字**：原始 210,488 行 → processed 207,858（98.7%）+ rejected 91（可追溯不物理删除）；流式清洗全程 ~18s；FTS5 查询 0.2–0.4ms；SHA-256 门禁 + 幂等全量重建（重跑 2 轮终态逐数一致）。

**核心情节（清洗规则修复）**：初版规则 `\*+` 全量删星号 → 抽样发现 11,032 行（5.24%）合法数学记法被毁（`27*324` 乘号、`cm**3` 指数）→ 重写为精确残留规则（仅 3 行真残留）→ **从原始文件全量重建** → 自写 21 万行独立重放核验器逐行比对 0 差异 → 恢复 11,054 行。教训成句：**"测试全绿 ≠ 数据正确"——29 项单测全过的情况下数据仍是坏的，只有数据层独立核验才能定案。**

**衍生发现**：扫出数据集填空标记 1,684 行（定性为模板而非损坏）、退化占位 585 行、并发现 1 例数据集自身缺陷（1070129：ans/equation 与题干真值 18.9 不一致）——审计报告可复现。

**面试追问点**：为什么流式不整载（210k×内存）；验算怎么做（AST 白名单安全求值）；rejected 为什么入库不删（可追溯）；去重键为什么不含星号。

## 故事 2：LLM 打标管线与 A/B 对照试验（Phase 1 / Step 5）⭐ LLM 工程化叙事

**数字**：DeepSeek-flash；500 题双臂对照实测 **¥2.85**（预估 ¥1.2 缓存态）；A 臂缓存命中率 **91.8%**（固定前缀缓存）vs B 臂 3.5%；单题 ¥0.00217；A 臂主知识点命中 89.8%、难度一致率 98%、合格率 81.6%（90% 放行线未达→治理循环设计，诚实记录）。

**工程机制（每条都是面试点）**：预算三线（¥10 提醒/¥15 暂停/¥20 硬停）+ 组级累计防绕过（台账初始值=历史批次费用之和——重试/续跑/新建批次都无法绕过）；并发原子预留（无缓存最坏口径，缓存命中不作保护前提）；幂等键 (q_id, prompt_version) + 断点续跑；AIMD 并发（429 降并发非升并发）；manifest 分层（运行级入 Git / 逐题明细入 staging）。

**评测设计**：助手盲标 gold → 用户裁决终版（49 confirmed + 1 pending，pending 不进分母）；A/B 双臂同题同模型同 gold；B 臂发现 embedding 召回天花板（recall@10=62%，13.5 字符 KP 描述短文本召回弱）——**用数据否决了"更便宜"的方案**。

**面试追问点**：为什么 A 臂比 B 臂还便宜（前缀缓存 0.04 元/M vs 候选块全 miss）；429 为什么降并发；81.6% 没达标怎么办（错误归因三桶 → prompt v2 消歧规则已实施待重跑）；如何防预算绕过。

## 故事 3：知识标签溯源体系（Phase 1 / Step 2+4+5）

**数字**：初中 303 KP + 374 前置边（课标拆条+人工抽检修正）；小学 82 KP 规则推导（编号冻结、零挂接如实报告 98.2% 覆盖）；规则标签与 LLM 标签双表隔离 + 消费视图（来源列显式）+ KP 定义版本链（kp_registry v1→v2 哈希链）。

**设计原则成句**：规则标签=候选非可信（55% 误挂率实测证据）；LLM 标签绝不继承规则结果（prompt 构造查询零 q_kp JOIN，单测断言）；KP 编号冻结保证跨运行稳定。

**面试追问点**：为什么双表不合并；视图回退逻辑（unmapped 永不回退规则）；KP 定义演进怎么不破坏历史批次（快照哈希落批次表）。

## 故事 4：学情归因 + 可观测（Phase 3，2026-11-17 关账）⭐ 确定性算法 + 真实成本

**数字**：小学前置图 **82 KP / 87 条教学依赖边**（DAG，用户审核冻结）；归因一致率 **10/10=100%**（10 例 GT，用户冻结 Gold）；演示班 6 条归因链（根因均「乘除运算」）→ 6 组 **18 道真实题库推荐**（source=ape210k、q_id 逐条可回查）；Trace 成本逐次记录：1 次真实 deepseek-flash 调用 tokens 712/1235 = **¥0.00515**（Σ明细=Σ步骤 `cost_recompute_ok`）；模板兜底任务成本 cost=NULL、前端显示「—」不以 ¥0 冒充。

**核心机制（每条都是面试点）**：掌握度 = 卷面分值 × 近期 2:1 × 主辅角色权重(λ=0.5) 加权均值；四状态（无覆盖/样本不足<3题/薄弱<0.6/正常）；主辅角色来自**独立映射清单**（F16 导入的 kp_ids 是主辅并集、不区分角色 → 角色清单按「考试标签+题号」解析）；归因 = 沿前置图反向回溯**最深 <0.7 节点**为根因，前置证据不足→**阻断不猜**、多分支→**冲突保留降置信**；推荐只出真实题（难度带）=`clamp(round(5×掌握度),1,5)` 降 1 档起步、候选不足如实不放宽；LLM 只做叙述且**模板兜底**（离线零 Key 可跑）。Trace/成本：**逐次调用落账**（含重试 attempt 编号）、价格版本+单价快照固化（历史成本不被调价改写）、`unavailable` 记 NULL 不伪装 0；重启后 `/trace` 库直读可回放。

**工程诚实（加分点）**：10/10 一致率明确标注「**只代表冻结案例上的算法行为一致性，不代表真实教学诊断准确率 100%**」；重启后 `/tasks/{id}`/`/citations`/`/files` 因进程内 task_store 缓存 404 的**已知限制如实记录、未擅自改**冻结逻辑；数据许可边界（APE210K 本地个人开发/测试可用、GitHub 只公开代码与统计报告不提交数据集本身）；全链路复现脚本入库（`eval_diagnosis.py` / `s6_e2e_review.py`）。

**辅助素材**：前端 F16「数据导入」页（模板下载/上传/批次状态/逐 Sheet 错误报告，直连后端零改动）+ 学情分析页（四状态/归因链可展开证据/推荐/PDF）+ 运行观测页（成本面板/Trace 时间线，NULL 显示「—」）——真实起服冒烟 + 401 pytest。

**面试追问点**：为什么主辅权重 0.5（Gold v2 标签原则：辅助=独立教学意义、非等同强度证据；λ 敏感性报告 0.5/1 翻转仅 1 KP）；近期权重为啥 2:1；前置图怎么来的（课标拆条 + 用户逐边冻结）；10/10 意味着什么、**不算**什么（教学准确率 ≠ 算法一致性）；NULL 不伪装 0 如何穿透到 trace 与前端；价格版本快照为什么（历史成本不被调价改写）。

## 故事 5：评测体系与 LLM-as-judge 校准（Phase 4，2026-11-18 完成）⭐ 评测方法论 + 诚实工程

**做了什么**：从零建评测体系——111 条 golden（core 80 + boundary 31，边界≥20%，全部小学化；用户逐条裁决冻结入 Git + eval_cases）→ Fake Runner（复刻当前实现的确定性 FakeLLM，证明链路正确：任务成功率 100%（93/93）、行为正确率 90.09%）→ 暴露系统短板（正确追问率 0%、正确拒绝率 66.7%、错误执行率 64.7%）→ Online 适配 + 成本统计（未知成本不视 0）+ 预算三线（¥10/¥15/¥20）+ **单次冒烟 ¥3/¥5 + 重试预留 + 超支核查** → 真实冒烟 20 条 ¥0.211 / 校准 50 条 ¥0.661（真实 usage 全量已知）→ judge 五维（LLM-as-judge）+ 校准 4 轮（46.4%→61.6%→64.0%→55.2%）→ **未达 80% 阈值：不回退标准，按规格回退规则评分并如实记录**（规则评分已应用到全量）→ eval API + 前端评测中心（分工作流 p95、baseline→current delta、judge 回退徽标）→ GitHub Actions CI（pytest 全量 + fake smoke 20）全绿，447 tests。

**数字**：111 golden / 4 类行为 / 4 轮 judge 校准 / 预算三线 + 单次更严 / 真实调用成本 ¥0.211+¥0.661+judge ¥1.34 / 447 passed / CI 50s。

**面试追问点**：①judge 为什么没采信（64%<80%，主观评分样本天花板；不调口径凑通过）；②成本未知怎么办（cost_known=False + 按最坏预留，不视 0）；③预算超支怎么办（预估软保护 + 结算后硬停；超支核查抓出 try_reserve 漏查暂停线的真实缺陷）；④Fake Runner 通过率 100% 能说明什么（只证明评测基础设施，不证明模型能力）；⑤gc_e03 诊断降级 28% 怎么处理（先量化、再决策业务修复，不拍脑袋调 prompt）；⑥为什么真实检索后不重跑校准（产物变则人工评分作废，避免重评 50 条）。

**工程诚实（加分点）**：judge 未采信如实回退；degraded 率、规则兜底弱（44.8%）、任务成功率分母口径错误（发现后修正并记录）全部如实入档；「不改标准凑通过」贯穿全程。

## 故事 6：质检环 Critique + MCP 能力开放（Phase 5，2026-11-19 完成）⭐ Agent 工程化 + 安全

**做了什么**：给 LLM 实时组卷（question_gen）加**质检回流环**——三维校验（正确性确定性规则 / 难度代理 / 批内+历史题库查重）→ LLM 一题一验（结构化 Schema）→ 不合格携带具体原因重生成（≤2 轮）→ 仍不合格剔除并记缺口、重算分值、全剔除则任务显式失败；质检三态降级（completed/partial/skipped），LLM 不可用时确定性规则照跑、未复核题不标完整通过；6 项指标（首轮/全轮拦截率、平均收敛轮次、剔除率、回流成功率、降级任务数）经 `03_质检报告.json` → `eval_runs.metrics` → 评测页展示（无数据返回 null）。同时把检索/题库/诊断三大能力以 **MCP** 开放：3 个工具全部复用服务层；stdio 本地受信 + Streamable HTTP 远程；普通/管理员双 Token + 敏感工具环境开关；复用 SecurityMiddleware 认证与 60/min 限流；启用 **DNS Rebinding 防护**（Host 越界 421 / Origin 越界 403）。

**数字**：critique 3 维 + ≤2 轮回流 + 3 态降级 + 6 指标；MCP SDK **mcp 2.3.0**、3 工具、2 传输、双 Token、31 项协议级测试；Phase 5 全量 **542 passed**。**真实 10 条 DeepSeek 验证（修复前基线）**：78 题、**¥0.861972**、1189.58s、**8/10 任务成功**（2 条因 critique 272.6s/175.6s 击穿 180s 超时）；**首轮拦截 26.92% / 全轮 40.00% / 平均收敛 1.277 / 剔除 5.13% / 回流 47.62% / 降级 10/10**；38/78 题 unverified。**修复后抽检（gc_q12 单 case）**：**completed、passed 5/6、unverified 0、12 轮**，首轮 66.7%/全轮 58.3%/收敛 2.0/回流 75%，¥0.075498。Phase 5 真实总花费 ≈ **¥1.1566**（另有 1 次未落盘诊断约 ¥0.001–0.002）。

**核心机制（每条都是面试点）**：①为什么质检只做 question_gen（exam_loop 用冻结题库、确定性基准不可被回流改变）；②规则层与 LLM 分工（规则不依赖模型、LLM 不可用仍跑规则；未复核 ≠ 通过）；③每轮重生成后**完整重检**而非只复查失败维度；④剔除后分值精确重分配、全剔除显式失败（禁止空试卷）；⑤MCP 2.x 迁移实测（FastMCP→MCPServer、async tool API、`structured_output=True` 需 pydantic 返回模型）；⑥**Token 认证不能替代 DNS Rebinding 防护**（Host/Origin 白名单独立生效）；⑦stdio 下 stdout 只走 JSON-RPC、日志走 stderr（防协议污染）；⑧敏感工具最小必要 + 审计（不记姓名/学号/完整 Token）；⑨**真实根因定位**：模型把长理由写进 `reasons` 漏引号 → 工具参数非法 JSON → provider 归一为 `{}`；修复为**短字段 schema + 理由走 content + `arguments_raw` 保留 + 保守解析修复**，不放宽 schema；⑩**critique 预算**：按工作流剩余时间收紧，耗尽转 partial 保留结果，不让 180s 全局超时杀掉整任务（gc_q03 真实验证）；⑪**单 case 抽检**：gc_q12 从 passed 1/unverified 5/partial → passed 5/unverified 0/completed，但仅单 case，不宣称整体提升。

**工程诚实（加分点）**：FakeLLM 与真实指标严格分离；整体真实指标是**修复前基线**且严重降级（26.92% 因 38 题 unverified 计入分母不计分子，是偏低下界；10/10 partial；2/10 超时）；修复后仅 **gc_q12 单 case 抽检通过**，**整体 10 条未复跑**，不宣称整体提升；MCP Inspector 图形界面未点验（以协议级测试 + stdio 子进程 + 真实 curl 起服等效覆盖）；Phase 4 遗留（全量 online / gc_e03 / ECS 部署）原样保留、不误标已解决。

**面试追问点**：质检为什么走两轮而不是一轮/无限轮；LLM 复核失败怎么保证不放过坏题；为什么大量 unverified、26.92% 为什么是下界；长理由漏引号问题怎么定位、为什么把理由移出工具参数、为什么不放宽 schema；critique 预算与全局超时怎么配合；单 case 抽检能说明什么、不能说明什么；MCP 为什么不在工具层重写业务；为什么敏感工具要第二个 Token 而不是同一 Token；DNS rebinding 攻击面到底在哪、认证为何不够；如何证明 stdio 没被日志污染。
